# scrapescope v1: module contracts

This is the developer reference for scrapescope's internals. It fixes the
public API of every module, the data that crosses module boundaries, the
forwarder's wire behaviour, the events file, report.json, the CLI surface and
the exit codes. User-facing behaviour is described in the README and the other
files in `docs/`; this file is for people changing the code.

How it came about: scrapescope v1 was built in parallel, with each part of the
tree owned separately (section 1), and this file was the contract between the
parts. The requirements came from ipvolt's internal project
plan and a build brief, which are not published; section 16 lists every place
where this file adds to or narrows the brief, with the reason, and section 17
quotes the brief's field lists. The "round N" notes record which review round
changed a rule. Where this file and the code disagree, treat it as a bug and
report it (CONTRIBUTING.md).

The executable half of the contract is `src/scrapescope/types.py` (shared
dataclasses, sanitisers, the events parser) and `src/scrapescope/config.py`
(upstream parsing, sizes, child environment, constants, exit codes). Import
from them; do not redefine their types or constants.

Ground rules for every role:

- Edit only files you own. The architect created stub files in your package;
  replace them freely, but keep the public names listed here importable from
  the package `__init__.py` shown in each section.
- Python >= 3.11, `from __future__ import annotations`, type hints, small
  focused modules, docstrings that state accuracy limits honestly. Source files
  are ASCII (use `\uXXXX` escapes, never literal control or bidi characters).
  Beware: file-writing tools may turn a `\u202e` you typed into the literal
  character. Check with Python (`[c for c in text if ord(c) > 127]`), since
  `grep -P '[\x80-\xff]'` misses them in some locales.
- Core dependencies are `h11` and `httpx[socks]` only. Playwright is the
  optional extra `[browser]`: import it lazily inside functions, never at module
  import time, so `import scrapescope.<anything>` works without it. Requests is
  a dev dependency only: `helpers.hooks` imports it lazily.
- No network access except the user's job, `find`'s page load and the one
  `--verify` request. No telemetry, update checks or DNS lookups of our own.
  Tests never touch the internet (section 15).
- Use the project's virtual environment for everything
  (`.venv/bin/python -m pytest tests/...`), with the project installed
  editable with the extras `browser,dev` (`pip install -e '.[browser,dev]'`).
  Dependencies change only through `pyproject.toml`.

### 2.1 `scrapescope.types`

Every dataclass mixes in `Serializable`: `to_dict()` gives JSON-compatible data
(tuples become lists; fields declared with `terminal_only(...)` are omitted),
`Cls.from_dict(d)` rebuilds it (unknown keys ignored, wrong types raise
`ValueError`). `to_dict()` does no redaction; the report builder does.

| Group | Types |
|---|---|
| Forwarder output | `TunnelRecord`, `BudgetEvent`, `HostBytes`, `TimelinePoint`, `Totals`, `MeterSnapshot` |
| Events file | `AttachEvent`, `LaunchEvent`, `RequestEvent`, `HelperEvent` (union), `parse_event(obj)`, `event_to_json_line(ev)` |
| find | `ChallengeResult`, `FindFlags`, `FindMatch`, `Coverage`, `VerifyResult`, `StarterCode`, `FindResult` |
| Attribution | `BucketTally`, `HostAttribution`, `PathBytes`, `TypeAllocation`, `Buckets`, `NonTargetHost`, `UnitsInfo`, `PerUnitBytes`, `SuccessInfo`, `BypassInfo`, `EventCounts`, `AttributionResult` |
| Model and snippets | `CostInfo`, `WhatIf`, `Fix` |
| Catalogs | `BackgroundEntry`, `ChallengeSignal`, `ChallengeVendor`, `DirectEntry`, `Catalogs` (with `from_documents`, `versions`, `background_entry_for`, `background_id_for`, `direct_entry_for`, `direct_id_for`, `vendor`) |
| Report | `ReportOptions` |
| Sanitisers | `clean_host`, `clean_path`, `safe_text`, `safe_code`, `validate_host_glob`, `host_glob_match`, `is_catalog_id`, `ip_literal`, `canonical_host` (round 3) |
| Constants | `EVENTS_VERSION = 1`, `REPORT_SCHEMA_VERSION = 1`, `BUCKET_*`, `TUNNEL_*`, `TARGET_ROUTES`, `COVERAGE_SKIP_LABELS`, `MAX_EVENT_LINE_BYTES = 4096` |

Key semantics:

- `MeterSnapshot.totals()` is the only place totals are computed. Every
  consumer (attribution, model, report) uses it.
- `TunnelRecord.bytes_with_connect` = upstream socket bytes both ways plus the
  synthetic CONNECT estimate (direct mode only); `bytes_without_connect` =
  upstream socket bytes minus real negotiation bytes; `counted_bytes` (budget
  basis) = upstream socket bytes both ways, negotiation included, synthetic
  excluded; `payload_bytes_sent/received` = upstream bytes minus negotiation.
- Host globs: lowercase `[a-z0-9_.:*-]`, `*` is the only wildcard and matches
  zero or more characters including dots; `*.example.com` does not match
  `example.com`. Matching is `host_glob_match(pattern, host)`.
- `clean_host` lowercases, strips IPv6 brackets and a trailing dot, IDNA-encodes
  and enforces `[a-z0-9_.:-]{1,253}`; IPv6 literals are stored without brackets.
  Round 3 (sec3-5): `ip_literal(host)` parses an IP literal the way
  `getaddrinfo` does (legacy IPv4 spellings follow `inet_aton`, so a leading
  zero means octal; `::ffff:a.b.c.d` is unmapped) and `canonical_host(host)`
  returns the canonical address for a literal, else the cleaned name:
  `1.2.3.04`, `0x01020304`, `16909060`, `1.2.772` and `::ffff:1.2.3.4` all
  become `1.2.3.4`. `validate_host_glob` canonicalises IP globs without `*`.
  `forwarder.upstream.ip_literal` re-exports it.
  `clean_path` drops query and fragment and every `;` path parameter, replaces
  token-like segments (a JWT, a UUID anywhere in the segment, a stem of 24+ hex
  characters, or of 32+ base64url characters with both cases, digits and at
  least four letter/digit alternations that are not word-like) with `{token}`
  keeping the file extension, percent-encodes non-printable/non-ASCII and caps
  at 512 characters (round 2, sec2-12). It is a heuristic: a kept path can
  still hold identifiers it does not recognise. The same cleaning applies to
  events-file paths and to the paths `find` shows in the terminal.
  `is_path_token_segment(segment)` is the one path-token test: `find`'s
  `looks_random_path_segment` calls it, so find flags exactly the segments
  reports hide. `safe_text` escapes every character of the
  Unicode categories Cc, Cf, Zl, Zp and Cs visibly (controls, C1, bidi marks,
  overrides and isolates, zero-width characters, the BOM, the tag block, line
  and paragraph separators, lone surrogates) and caps length; use it on every
  untrusted string you print. `safe_code` does the same but keeps newlines and
  tabs. The schema's `text` and `code` patterns reject the same characters
  (listed as explicit ranges, generated from Unicode 15.0; astral ranges are
  literal characters, so the patterns also work as ECMAScript `u` regexes).

## 3. Forwarder

Package `scrapescope.forwarder` (modules `server.py` for listeners and HTTP
framing, `upstream.py` for HTTP CONNECT/SOCKS5/direct, `meter.py` for counters,
budget and timeline). stdlib asyncio plus h11.

### 3.1 API

```python
from scrapescope.forwarder import Forwarder, ForwarderThread, ForwarderError

class ForwarderError(Exception): ...        # startup failure (port in use, bad config); CLI exit 88

class Forwarder:
    def __init__(self, config: ForwarderConfig, *,
                 connect_map: ConnectMap | None = None,
                 clock: Callable[[], float] = time.time) -> None: ...
    async def start(self) -> None            # bind 127.0.0.1:config.port (+ auth listener when config.auth_listener)
    async def stop(self) -> None             # close listeners and every tunnel; idempotent
    @property port -> int                    # valid after start()
    @property auth_port -> int | None        # the credential-challenging listener, or None
    @property url -> str                     # "http://127.0.0.1:<port>"
    @property auth_url -> str | None         # "http://127.0.0.1:<auth_port>" or None
    @property budget_tripped -> bool
    def snapshot(self) -> MeterSnapshot      # loop thread only; returns deep copies
    def on_budget(self, callback: Callable[[BudgetEvent], None]) -> None
        # called on the loop thread for warn_80, tripped and tunnel_cap events;
        # exceptions raised by callbacks are caught and counted in internal_errors
    def open_tunnel_count(self) -> int       # cheap: tunnels still open (the runner's drain loop polls it)

class ForwarderThread:
    """Runs a Forwarder on its own event loop in a daemon thread."""
    def __init__(self, config: ForwarderConfig, *, connect_map: ConnectMap | None = None) -> None: ...
    def start(self, timeout: float = 10.0) -> None        # returns once listening; startup errors re-raised as ForwarderError
    def stop(self, timeout: float = 10.0) -> MeterSnapshot  # idempotent; returns the final snapshot
    def __enter__(self) -> "ForwarderThread"              # start()
    def __exit__(self, *exc) -> None                      # stop()
    port, auth_port, url, auth_url                        # same as Forwarder, valid after start()
    def snapshot(self, timeout: float = 5.0) -> MeterSnapshot   # thread-safe
    def on_budget(self, callback) -> None                 # callback runs on the forwarder thread: keep it short, thread-safe
    budget_tripped: threading.Event                       # set when the budget trips
    error: BaseException | None                           # set if the loop died unexpectedly (runner exits 88)
    def open_tunnel_count(self) -> int                    # thread-safe; no full snapshot
```

`ForwarderConfig` (in `config.py`): `upstream` (None = direct/sizing mode),
`token`, `require_token` (serve: always True, round 4 hon4-3; run/find:
False), `auth_listener` (run/find: True), `port` (0 = random), `budget_bytes`,
`max_tunnel_bytes`, `deny_rules: tuple[HostRule]`, `direct_rules:
tuple[HostRule]` (only under `--env-all`), `connect_timeout_s = 30`,
`idle_timeout_s >= 600`, `budget_warn_fraction = 0.8`,
`timeline_resolution_s = 0.25`, `allow_private_targets = False`
(`--allow-private-targets`: direct routes may reach non-global addresses),
`record_timeline = True` (round 2: `serve` sets False and keeps no timeline,
which its report never used), and the property `mode`.

`HostRule(pattern, label)`: labels are `deny-host:<glob>`,
`catalog:background:<entry id>`, or, for direct rules, the direct.json entry id.

`connect_map: {(host, port): (ip, port)}` (test only). When it is not None, the
meter's own direct connections (direct mode and non-target carriage) use it,
and every name that is not in it fails with `failed:dns` without touching DNS.
Mapped entries are exempt from the private-address check (they point at
loopback fixtures); the self-loop check still applies. Loopback IP literals
that are not in the map connect as given, but go through the private-address
check like any direct destination, so they need `allow_private_targets`. It
never affects the connection to the upstream proxy itself.

### 3.2 Listeners and the requests they accept

- Bind `127.0.0.1` only, never `0.0.0.0` or `::`. The main listener uses
  `config.port`; the auth listener (run/find) always uses a random port.
- Accepted: `CONNECT host:port` and absolute-form `http://` requests (any
  method). Everything else is refused before any upstream contact:

| Client request | Response | Recorded as |
|---|---|---|
| absolute-form `https://...` | `400`, `X-Scrapescope-Error: https-absolute-form` (no TLS origination) | `refused["https_absolute_form"]` |
| origin-form (`GET /x`), asterisk-form, or any other form | `403`, `Content-Length: 0`, `Connection: close`, no body and no scrapescope headers (DNS-rebinding defence) | `refused["origin_form"]` |
| malformed request or authority, bad port | `400`, `X-Scrapescope-Error: bad-request` | `refused["bad_request"]` |
| target is the meter itself (`localhost` or a loopback literal, port = `port` or `auth_port`). Literals are parsed like `getaddrinfo`: legacy IPv4 spellings (`127.1`, `0x7f.0.0.1`, `2130706433`, `127.000.000.001`, `0177.0.0.1`) and `::ffff:127.0.0.1` count | `403`, `X-Scrapescope-Error: self-loop` | `refused["self_loop"]` |
| token required, missing or not `ss-<token>`-prefixed | `407`, `Proxy-Authenticate: Basic realm="scrapescope"` | `refused["token_required"]` |
| username starts with `ss-` but the token part is wrong (any mode) | `407`, same header | `refused["bad_token"]` |
| auth listener and no `Proxy-Authorization` | `407`, same header | `refused["auth_challenge"]` |
| budget already tripped | `403`, `X-Scrapescope-Budget: tripped`, `X-Scrapescope-Error: budget` | `refused["budget"]` |
| host matches a deny rule | `403`, `X-Scrapescope-Error: denied` | a TunnelRecord: route `refused`, status `denied`, `rule` = label |

Checks run in this order: request form, authority, self-loop, token/credentials,
budget, deny rules, routing. Round 3 (sec3-5): an IP-literal host is
canonicalised (`types.canonical_host`) before the self-loop, deny, direct-rule
and routing checks and in TunnelRecords and reports; what an HTTP CONNECT
upstream receives (the CONNECT line, the plain-HTTP target and `Host`) keeps
the client's spelling. Two further self-loops are caught at connect
time, as a TunnelRecord with status `failed:self_loop` and a `403 self-loop`
reply: a hostname that resolves to the meter's own port, and an upstream proxy
name that resolves to the meter. The start-time upstream URL check covers the
legacy spellings. The meter's own responses are
`HTTP/1.1 <code> <reason>`, `Content-Type: text/plain; charset=utf-8`,
`Content-Length`, `Connection: close`, `X-Scrapescope-Error: <code>` (except the
bare origin-form 403) and a fixed one-line body. They never echo request
content. The meter serves no readable pages at all.

### 3.3 Credentials

`auth = parse_basic_auth(Proxy-Authorization)` of the client request; token =
`config.token`.

| Client credentials | Action | `TunnelRecord.auth` |
|---|---|---|
| none | main listener with `require_token` or auth listener: 407. Otherwise inject the configured upstream credentials, if any | `injected` or `none` |
| username exactly `ss-<token>` (password ignored) | strip; inject configured upstream credentials | `injected` or `none` |
| username `ss-<token>~<user>`, any password | forward `<user>:<password>` | `token-mapped` |
| username starting with `ss-` otherwise (token None: not applicable) | local 407, never forwarded | refused `bad_token` |
| other credentials | `require_token`: 407. Otherwise pass through unchanged | `passthrough` |
| non-Basic `Proxy-Authorization` | `require_token`: 407. HTTP upstream: passed through unchanged. SOCKS5: 502 `socks-auth-unsupported` | `passthrough` |

- HTTP CONNECT upstream: the client's CONNECT request line and headers are
  forwarded unchanged (providers use custom CONNECT headers) except
  `Proxy-Authorization`, which is set, replaced or removed per the table. Plain
  HTTP requests stay absolute-form with the same `Proxy-Authorization` rule and
  the normalisation of section 3.5; round 2: their request target is rebuilt
  as `http://<authority as routed><origin-form path and query>`, with the
  fragment dropped, instead of the raw client request-target.
- SOCKS5 upstream: credentials map to RFC 1929 (offer method 0x02 when
  credentials exist, else 0x00). Hostnames go as ATYP 0x03 (remote DNS); only
  IP literals use 0x01/0x04 (round 3: a legacy IPv4 spelling such as
  `0x01020304` counts as a literal and goes as ATYP 0x01 with the canonical
  address, no longer as a name). Plain HTTP is sent origin-form with
  `Proxy-Authorization` and `Proxy-Connection` removed.
- Direct mode: client credentials are dropped, never sent anywhere; token rules
  still apply.
- The upstream's CONNECT reply (status line, headers such as `407`,
  `Proxy-Authenticate`, `502` and vendor error headers, and body) is relayed to
  the client verbatim. After relaying a non-2xx reply the meter closes both
  connections.
- Never log, print or store `Proxy-Authorization`, the upstream URL, host,
  username or password.

### 3.4 Routing

In this order:

1. Deny rules (403, recorded as denied). They apply in every mode.
2. `direct_rules` match (only set under `run --env-all`): connect directly (DNS
   or connect map), route `non-target`, `rule` = direct.json id. This is the one
   case where, with an upstream configured, the meter resolves a target name
   itself and connects from this machine's own IP address, for every client of
   the meter, the browser included. `run` prints a note saying so at start
   (unless `--quiet`), and the report carries a warning when such tunnels
   occurred. Non-target routes are exempt from the private-address check.
   Non-target bytes are excluded from the budget, timeline, totals and hosts;
   they appear only in `non_target[]`.
3. Upstream configured: route `http-connect` or `socks5`. The target hostname is
   passed to the upstream unresolved; the meter never resolves target names on
   these routes.
4. Otherwise route `direct` (sizing mode; the meter resolves the name itself, or
   uses the connect map in tests). It resolves once, refuses non-global
   destinations (loopback, RFC 1918, link-local including 169.254.169.254,
   CGNAT, ULA, unspecified, reserved, multicast; IPv4-mapped addresses are
   unmapped) with `403 private-address` (status `failed:private_address`)
   unless `allow_private_targets`, and connects only to the checked addresses
   (DNS pinning). Round 4 (sec4-1): IPv6 forms that embed an IPv4 address are
   judged by that address as well (`types.embedded_ipv4`): IPv4-mapped, the
   NAT64 well-known prefix `64:ff9b::/96`, IPv4-translated `::ffff:0:a.b.c.d`
   and IPv4-compatible `::a.b.c.d`. Site-local `fec0::/10`, 6to4 `2002::/16`
   and local-use NAT64 `64:ff9b:1::/48` are always refused
   (`upstream.is_private_destination`). Limit: NAT64 prefixes that a
   particular network chooses cannot be recognised. Deny rules on an IPv4
   address or glob also match those IPv6 forms (section 3.2's deny step
   compares the embedded address too). Records keep the IPv6 address
   (IPv4-mapped ones become the IPv4 address through `canonical_host`), and
   a provider still receives the client's own spelling. Round 3 (sec3-1): after the TCP connect and before any byte
   is written it also refuses, with the same 403 and status, a connection
   that reached this machine (the peer equals the socket's own source
   address: a service bound to all interfaces answers on this machine's
   global addresses) and, for IPv6, a peer in the same /64 as the source
   address (hosts on this machine's own link);
   `upstream.check_not_own_address`. `allow_private_targets` permits both;
   non-target routes and test connect-map entries are exempt. Limit: IPv4
   netmasks are not visible, so IPv4 LAN hosts with public addresses are not
   caught. The meter's `private-address` message and `run`'s failure hint
   name this machine and its own link.

Round 2: on the direct and non-target routes, a name with several resolved
addresses is tried Happy-Eyeballs style (RFC 8305): families interleaved, a
new attempt every 250 ms (`HAPPY_EYEBALLS_DELAY_S`) or as soon as one fails,
one overall connect deadline. A blackholed first address no longer costs the
whole timeout. The first connection wins; the others are closed before a byte
is written.

Exactly one upstream connection per client connection at any time, never
pooled or shared. A tunnel (TunnelRecord) is one client connection's traffic
to a single authority over one upstream connection. Round 3 (meas3-3): if a
keep-alive plain-HTTP client connection switches authority on the
`http-connect` route, whose peer is the provider, the meter keeps the provider
connection, as clients such as Requests, urllib3 and Chromium do, and starts a
new TunnelRecord at the request boundary with `continued_from` set to the
previous record's id; bytes are charged to the record of the exchange in
flight (the meter never pipelines upstream). On the `socks5`, `direct` and
`non-target` routes the upstream connection belongs to one target, so the
meter closes it and opens a new one with a new record. Records therefore no
longer equal upstream connections: count connections with
`TunnelRecord.opened_connection` (`continued_from is None` and the route is
not `refused`).

### 3.5 Plain HTTP (h11)

Keep-alive through h11 on both sides; chunked and close-delimited bodies, HEAD,
1xx (including `Expect: 100-continue`), 204 and 304 handled; `Upgrade`
(ws://) switches to a raw byte relay after `101`. Response bodies are relayed as
they arrive (streaming, bounded buffers), never accumulated in memory.

Added in round 1 (applies to absolute-form requests on every route; CONNECT
heads are still forwarded unchanged):

- `Host` is always set to the absolute-form target's authority; a foreign
  `Host` is replaced.
- Hop-by-hop request headers are removed: `Keep-Alive`, `Proxy-Connection` and
  any header listed in `Connection`, except the framing headers, `Host`,
  `Proxy-Authorization`, `Upgrade` and `TE`. `Connection` is rewritten to the
  options that still apply (`close`, `upgrade`, `te`).
- A request with both `Content-Length` and `Transfer-Encoding` gets `400
  bad-request`.
- Chunked trailers are relayed in both directions, except to HTTP/1.0 clients.
- Round 4 (meas4-4): before h11 parses a response head, the meter removes
  whitespace between a field name and its colon (RFC 9112 section 5.1
  requires a server to reject such a field in a request; in a response a
  proxy must remove it). A response with `Transfer-Encoding: <codings>,
  chunked` (for example `gzip, chunked`) is relayed to HTTP/1.1 clients with
  that header value and the chunk-framed body; the chunk sizes may differ,
  as for any plain-HTTP body the meter re-frames. HTTP/1.0 clients still get
  `502 upstream-protocol-error` for such a response, since the meter does not
  decode transfer codings. Other malformed response heads are still `502
  upstream-protocol-error`.
- Round 3 (meas3-10): 1xx responses other than 101 are not relayed to HTTP/1.0
  clients (RFC 9110 section 15.2).
- When a final response arrives while the client waits for `100 Continue`, or
  either side closes after the response, the meter relays the response and then
  closes the client connection with a lingering close; it does not wait for the
  request body.

Round 2 (keep-alive race): if a reused upstream connection closes or resets
after a request was forwarded but before any byte of its reply, the meter
closes (or resets) the client connection without a reply, so the client's own
retry applies, and the tunnel is `ok`. A first request on a fresh upstream
connection still gets `502 upstream-closed`.

### 3.6 Counting (the core contract)

- Count at the upstream socket, per tunnel: every byte written to it adds to
  `upstream_bytes_sent` when it is handed to the transport; every byte read
  from it adds to `upstream_bytes_received` as soon as it is read, before it is
  relayed. Round 2: an abort (budget, tunnel cap, stop, idle) uncounts
  whatever was still queued in the transport (`Meter.discard_sent`), so
  `upstream_bytes_sent` means bytes handed to the kernel. After a trip,
  `counted_bytes` can therefore end slightly below the trip event's
  `counted_bytes`, which is the count the meter decided on; the trip stays in
  force.
- Negotiation: the CONNECT request head written plus the CONNECT reply head read
  (plus the body of a relayed non-2xx reply), or every SOCKS greeting, method
  reply, RFC 1929 exchange and CONNECT request/reply. Negotiation bytes are
  inside `upstream_bytes_*` and also recorded in `negotiation_bytes_*`. Bytes read
  after a 2xx reply head in the same read are payload.
- `connect_request_bytes` = the full CONNECT head sent upstream;
  `proxy_authorization_bytes` = `len(b"Proxy-Authorization: " + value + b"\r\n")`
  when sent, else 0.
- Direct mode, kind `connect`: set `synthetic_negotiation_bytes_sent/received`
  from `config.synthetic_connect_sizes(host, port)`, then (round 2, meas2-9)
  replace the sent size with the length of the client's own CONNECT head as it
  would be forwarded to an HTTP CONNECT upstream, without `Proxy-Authorization`
  (`Meter.set_synthetic_request_bytes`; Chromium's head is about 236 bytes, the
  minimal one 63 for `origin-a.test:443`). Provider credentials are not
  included. Not added to upstream bytes or the budget; they make the
  with-CONNECT figure an estimate. Round 3 (meas3-9, documented, not
  estimated): plain-HTTP requests in direct mode go to the target in origin
  form without `Proxy-Authorization`, while a provider would receive the
  absolute-form target and the credentials line on every request; no
  synthetic bytes are added for them, and `with_connect_estimated` reflects
  CONNECT tunnels only (docs/accuracy.md).
- `upstream_status`: the CONNECT reply status (kind connect, HTTP upstream) or
  the last relayed response status (kind http). `socks_reply`: SOCKS REP.
- Timeline: target-tunnel bytes (both directions) are added to the bucket
  `floor(t / resolution) * resolution`; only non-empty buckets are kept.
  Round 2: at most `MAX_TIMELINE_SLOTS` (16,384) slots; beyond that adjacent
  slots merge and the resolution doubles, and
  `MeterSnapshot.timeline_resolution_s` reports the step in use. With
  `record_timeline=False` no slots are kept.
- `client_bytes_*` are diagnostics, never used for totals.
- Status values: `open` while running; `ok` for a normal close (including
  closes at `stop()`); `failed:<reason>`; `denied`; `budget` (closed by a
  budget trip); `tunnel_cap` (closed by `--max-tunnel-mb`). Failure reasons:

| Situation | Client gets | status |
|---|---|---|
| HTTP upstream replies non-2xx to CONNECT | the reply relayed verbatim | `failed:upstream_status` (`upstream_status` set) |
| round 3 (meas3-7): on the `http-connect` route, a kind-`http` record whose final responses were all 407 (the provider's answer) | the reply relayed verbatim | `failed:upstream_status` (`upstream_status` 407); a 407 followed by another status on the same record stays `ok`; a 407 on the direct or SOCKS5 routes comes from the origin and is not converted (`Tunnel.ok_status`, applied by `Meter.finish` for `ok`) |
| upstream refuses or is unreachable | `502`, `upstream-unreachable` | `failed:upstream_unreachable` |
| upstream connect timeout (name resolution and TCP connect, 30 s), or, round 4 (meas4-3), no HTTP CONNECT reply head or SOCKS5 negotiation reply within the idle timeout (600 s) | `504`, `upstream-timeout` | `failed:upstream_timeout` |
| upstream closes before replying | `502`, `upstream-closed` | `failed:upstream_closed` |
| SOCKS5 auth rejected | `502`, `socks-auth-failed` | `failed:socks_auth` |
| SOCKS5 no acceptable method | `502`, `socks-no-method` | `failed:socks_method` |
| SOCKS5 REP != 0 | `502`, `socks-reply-<n>` | `failed:socks_reply_<n>` (`socks_reply` set) |
| direct: name does not resolve (or is absent from a test connect map) | `502`, `dns-failed` | `failed:dns` |
| direct: connection refused / timeout | `502` `connect-refused` / `504` `connect-timeout` | `failed:connect_refused` / `failed:connect_timeout` |
| client went away before the tunnel was up (round 4: while the meter waits for the provider's CONNECT or SOCKS5 reply, a client reset, or an end of stream before the client sent anything, ends the wait at once and closes the provider connection) | none | `failed:client_closed` |
| unexpected exception | `502`, `internal-error` when still possible | `failed:internal` and `internal_errors += 1` |
| upstream reply is not valid HTTP (CONNECT reply or plain-HTTP response) | `502`, `upstream-protocol-error` | `failed:upstream_protocol` |
| non-Basic `Proxy-Authorization`, or credentials over 255 bytes, on a SOCKS5 route | `502`, `socks-auth-unsupported` | `failed:socks_auth_unsupported` |
| direct route to a non-global address without `allow_private_targets` | `403`, `private-address` | `failed:private_address` |
| a name or provider name that resolves to the meter itself (connect time) | `403`, `self-loop` | `failed:self_loop` |
| the upstream resets the connection during a relay (CONNECT tunnel, upgraded connection, or plain HTTP mid-response) | a TCP reset, not a clean close | `failed:upstream_reset` |
| round 3 (meas3-6): the upstream resets while a plain-HTTP request body is being forwarded | `502 upstream-closed` if no response byte reached the client, otherwise a reset | `failed:upstream_reset`; if the whole response had already arrived (for example a 413 followed by a reset of the rest of the upload), the response is relayed, the tunnel is `ok` and the client connection ends with a lingering close. The keep-alive race rule (section 3.5) still applies to reused connections |
| the meter ran out of file descriptors (EMFILE/ENFILE) opening the upstream socket (round 2) | `503`, `local-limit` | `failed:local_limit` |

A client reset is passed to the upstream as a reset; that tunnel stays `ok`.

(The client-visible code in the middle column is the `X-Scrapescope-Error` value;
`_MESSAGES` in `forwarder/server.py` holds each code's fixed one-line body,
`local-limit` included.)

Round 2: `MeterSnapshot.accept_limit_errors` counts the times a listener's
`accept()` failed for lack of descriptors (asyncio then pauses accepting on
that listener for about 1 s and retries). `run`, `serve` and `find` raise
their own soft `RLIMIT_NOFILE` to `min(hard, 65536)`
(`forwarder.limits.raise_open_file_limit`); `run` does it after starting the
job, so the job keeps its original limit. With a soft limit below 1,024 after
that, the runner prints a start note, and a report warning says that
`local_limit` failures and accept pauses came from this machine. Reports
carry both as `tunnel_failures` and `accept_limit_errors` (section 11.1).

Additions recorded at integration (forwarder role):

- kind `http` tunnels: `proxy_authorization_bytes` is the sum over every
  request forwarded on the tunnel; `upstream_status` is the last relayed
  status (101 after an upgrade).
- Direct and non-target tunnels always record `auth = "none"`.
- A request without a `Host` header is accepted (Python 3.11's http.client
  sends CONNECT without one); a CONNECT is forwarded unchanged, so a strict
  upstream may answer 400, which is relayed verbatim.
- After each of its own refusal replies the meter keeps reading for up to 1 s
  before closing, so the reply is not lost to a TCP reset.
- `Forwarder.snapshot()` is thread-safe (the meter's counters are guarded by a
  lock); `ForwarderThread.stop()` is idempotent and returns the final snapshot.
  A snapshot holds the lock only for open and changed records; per-record
  copies are made outside it. Retained records still grow for the
  forwarder's lifetime, with no cap yet: measured in round 3 (sec3-9), about
  0.4 kB per record in the meter, about 0.8 kB once the snapshot cache holds
  its copy, about 1.1 kB while a snapshot is alive. Deny-rule refusals create
  records before any provider contact and count no bytes, so the budget does
  not bound them (docs/security.md, "Resource use").
- An upstream URL that points at the meter's own listening port raises
  `ForwarderError` at start.

### 3.7 Budget, tunnel cap, deny

- The budget counter (`MeterSnapshot.counted_bytes`) is the sum of
  `counted_bytes` over target tunnels, failed ones included. It counts on read,
  including the read slice that trips it (relaying that slice is optional).
- At `counted >= budget_warn_fraction * budget_bytes`, once: `BudgetEvent(kind="warn_80")`.
- At `counted >= budget_bytes`: `BudgetEvent(kind="tripped", top_hosts=<up to 10
  heaviest target hosts by upstream bytes in the last TOP_HOSTS_WINDOW_S seconds>,
  closed_tunnels=n)`; close every open tunnel (status `budget`), refuse all new
  requests with 403 and `X-Scrapescope-Budget: tripped` until the forwarder
  stops, set `budget_tripped`, invoke the callbacks. The runner stops the child.
- `max_tunnel_bytes` (from `--max-tunnel-mb N`, N x 10^6 bytes regardless of
  `--gib`): when one upstream connection's counted bytes reach it, close only
  that connection (status `tunnel_cap`) and emit
  `BudgetEvent(kind="tunnel_cap", counted_bytes=<the connection's count>,
  limit_bytes=<cap>, tunnel_id=<the record that reached the cap>, host)`.
  Round 4 (meas4-6): it applies per upstream connection, not per record: on
  the `http-connect` route a kept provider connection's count includes every
  continued record (`continued_from`). One HTTP/2 tunnel can carry many
  responses, and one kept plain-HTTP connection several hosts' requests.
- The meter stops at its own count: bytes already in flight at the provider can
  add roughly (open tunnels x a few MB). Say so in docstrings and docs (user
  text avoids "a floor, not a cap", which reads like a minimum). The e2e budget
  test measures it: the fixture upstream handed over about 80 KB more than the
  meter read before it aborted the tunnel.
- A trip also closes open non-target tunnels and idle keep-alive plain-HTTP
  tunnels, because they are open tunnels.

### 3.8 Timeouts and edges

No idle timeout below 600 s; connect timeout 30 s (round 2: one overall
deadline across the Happy-Eyeballs attempts of section 3.4). Round 4
(meas4-3): `connect_timeout_s` bounds only name resolution and the TCP
connect. The HTTP CONNECT reply head and the SOCKS5 negotiation may take up
to the idle timeout (600 s), since a provider may hold CONNECT while it finds
a peer or retries the target; the body of a non-2xx CONNECT reply is still
read within 30 s. While the meter waits, a client that resets, or closes
without having sent anything, ends the wait at once: the provider connection
closes and the status is `failed:client_closed`. Bytes a client sends before
the 200 are kept (up to one head's worth, then TCP backpressure) and relayed
first once the tunnel is up; a half-close after such bytes is passed on after
the 200. Half-close
propagates (EOF from one side becomes `write_eof()` on the other while the
reverse direction keeps flowing). Round 2 (sec2-6, integrating verifier): a
client connection that has not delivered one complete request head
`FIRST_REQUEST_TIMEOUT_S` (60 s) after it was accepted is closed, however
slowly it keeps sending; the 600 s idle timeout applies once a request head
arrived. Real clients send their CONNECT or request as soon as they connect
(an exception would be a client that opens proxy connections in advance and
leaves them unused for a minute; it would simply reconnect). The meter never
changes hostnames or usernames and opens no connections of its own (round 3:
upstream connections == records with `opened_connection`; section 3.4). Its added latency
can change a browser's HTTP/1.1 connection scheduling: on loopback Chromium
opened one extra connection in most three-page runs, while with a 20 ms
provider-like delay the counts matched
(`tests/test_forwarder_browser.py::test_connection_pattern_with_and_without_the_meter_under_provider_latency`
bounds the difference at two).

### 3.9 Logging

Logger `scrapescope.forwarder`, DEBUG by default off. Allowed fields: tunnel id,
target authority, kind, route, status, byte counts. Never headers, paths,
queries, credentials or the upstream host.

## 4. Events file (helper to meter)

The runner creates a private file (`PrivateEventsFile`: 0600 inside a 0700
temp dir) and passes its path to the child as `SCRAPESCOPE_EVENTS`. Helpers and
hooks in the child append JSON lines; the runner reads them after the child
exits. There is no network metadata channel in v1.

- Format: UTF-8 JSONL, one object per line, at most 4096 bytes per line
  (`MAX_EVENT_LINE_BYTES`). Every object has `v: 1` and `kind`.
- Writers must: open the existing file with `O_WRONLY | O_APPEND` (never create
  it, never follow a missing path), write each line with one `os.write` call,
  build lines only with `types.event_to_json_line(event)`, never raise into the
  user's code (swallow and warn once), and emit only network schemes
  (`http`, `https`, `ws`, `wss`); `data:`, `blob:`, `about:`, `chrome:` and
  extension URLs are never written.
- Readers must parse each line with `types.parse_event(json.loads(line))` and
  drop (and count) invalid lines, lines over the size cap and lines whose `v` is
  not 1. Unknown keys are ignored.

Kinds and fields (all timestamps are `time.time()` wall-clock seconds):

```jsonc
{"v":1,"kind":"attach","ts":1790000000.12,"source":"playwright","pid":4242,"context":"4242-1"}
{"v":1,"kind":"launch","ts":1790000000.05,"source":"playwright","pid":4242,"browser":"chromium"}
{"v":1,"kind":"request","ts":1790000001.50,"source":"playwright","host":"origin-a.test","port":443,
 "scheme":"https","method":"GET","resource_type":"document","status":200,"failed":false,
 "from_cache":false,"from_service_worker":false,"frame":"main","is_navigation":true,
 "encoded_body_bytes":18234,"response_header_bytes":412,"request_header_bytes":608,
 "request_body_bytes":0,"sent_cookies":false,"sent_authorization":false,"context":"4242-1"}
```

| Field | Type | Meaning |
|---|---|---|
| `ts` | number | request start time when known (Playwright: when the `request` event fired), else when the event was recorded |
| `source` | `playwright` \| `requests` \| `httpx` | writer |
| `host` | string | URL host, lowercase, IDNA; validated by `clean_host`. Round 4: IP literals in canonical form (`types.canonical_host`, via `helpers.events.url_parts`): `1.2.3.04` is `1.2.3.4`, `[2001:db8:0:0::1]` is `2001:db8::1`, Chromium's `::ffff:102:304` is `1.2.3.4`, as in the meter's records |
| `port` | int or null | explicit or default port of the URL |
| `scheme` | `http` \| `https` \| `ws` \| `wss` | URL scheme |
| `path` | string, optional | ONLY when `SCRAPESCOPE_KEEP_URLS=1`; never the query or fragment |
| `method` | `[A-Z]{1,16}` | request method |
| `resource_type` | `[a-z_]{1,32}` | Playwright `request.resource_type` (`document`, `stylesheet`, `image`, `media`, `font`, `script`, `texttrack`, `xhr`, `fetch`, `eventsource`, `websocket`, `manifest`, `other`); hooks use `http_client` |
| `status` | int or null | response status; null when failed before a response |
| `failed` | bool | `requestfailed` fired, or the hook saw an exception |
| `from_cache` | bool | served from the HTTP cache (no network) |
| `from_service_worker` | bool | page request answered by a service worker (the worker's own fetch is a separate event with `frame: "service_worker"`) |
| `frame` | `main` \| `sub` \| `worker` \| `service_worker` \| `other` | who issued it; hooks use `other` |
| `is_navigation` | bool | Playwright `request.is_navigation_request()`; hooks false |
| `encoded_body_bytes` | int or null | Playwright `sizes()["responseBodySize"]`; hooks: encoded bytes read when known. Null for failed requests (Playwright's figure there is the declared Content-Length). On HTTP/2 and HTTP/3 it includes the response header frames |
| `response_header_bytes` | int or null | Playwright `sizes()["responseHeadersSize"]`; null on HTTP/2 and HTTP/3 |
| `request_header_bytes` | int or null | Playwright `sizes()["requestHeadersSize"]`; null on HTTP/2 and HTTP/3 (Playwright rebuilds it as HTTP/1.1 text). Playwright builds it as method + pathname + ` HTTP/1.1` plus the raw headers (each name + value + 4), with no query and no final CRLF, so it sits slightly below the wire on every route. Round 4 (meas4-5): for plain `http://` requests the proxy-hop headers Chromium sends to the meter (`Proxy-Connection`; `Proxy-Authorization` after a 407) are subtracted (`helpers.playwright._proxy_hop_bytes`), since the meter removes them |
| `request_body_bytes` | int or null | Playwright `sizes()["requestBodySize"]` |
| `sent_cookies` | bool | a `Cookie` header was sent (presence only) |
| `sent_authorization` | bool | an `Authorization` header was sent (presence only) |
| `context` | string, optional | opaque `[A-Za-z0-9_.:-]{1,64}` id tying requests to their context's attach event |

Never bodies, cookies, header values, credentials or query strings.

Round 2 (meas2-1): a request line may carry an optional `"no_network":
"fulfilled" | "aborted" | "blocked"` (`helpers.events.NO_NETWORK_KEY`) for a
request answered or stopped before the network (`route.fulfill`,
`route.abort`, a browser block such as mixed content or CSP). `types.parse_event`
still ignores the key; `attribution.read_events` turns such lines into
`attribution.NoNetworkRequestEvent` (`hit_network` False). They stay out of the
status histogram, allocation and the bypass check, and a warning counts them by
kind. Decision (integrating verifier, round 2): no first-class
`RequestEvent.no_network` field or report schema field in v1; the report
prints one combined "not network requests" line plus that warning.

`RequestEvent.reported_bytes` = sum of the four size fields (None as 0).
`RequestEvent.hit_network` = not `from_cache` and not `from_service_worker`
(and, for `NoNetworkRequestEvent`, always False).

## 5. Helpers

Package `scrapescope.helpers`. `helpers/__init__.py` imports nothing heavy.
All helpers are no-ops, with ONE `RuntimeWarning` per process, when
`SCRAPESCOPE_EVENTS` is unset ("scrapescope helpers inactive:
SCRAPESCOPE_EVENTS is not set; run the job under `scrapescope run`"). They
never raise into the user's code because of scrapescope problems.

### 5.1 `scrapescope.helpers.events`

```python
def enabled() -> bool                     # SCRAPESCOPE_EVENTS set and the file exists
def events_path() -> str | None
def emit(event: HelperEvent) -> None      # append one line (section 4 rules); never raises
def keep_urls() -> bool                   # SCRAPESCOPE_KEEP_URLS == "1"
def new_context_id() -> str               # f"{os.getpid()}-{n}"
```

### 5.2 `scrapescope.helpers.playwright` (sync and async APIs)

```python
def proxy_settings(*, username: str | None = None, password: str | None = None) -> dict | None
    # Browser-wide proxy for launch(proxy=...): {"server": SCRAPESCOPE_PROXY_URL}.
    # With username/password: {"server": SCRAPESCOPE_AUTH_PROXY_URL (fallback PROXY_URL),
    #  "username": ..., "password": ...} passed through unchanged.
    # None (plus the one warning) when SCRAPESCOPE_PROXY_URL is unset.
def instrument(context) -> context        # sync or async BrowserContext; idempotent
    # Writes an "attach" event, then listens at CONTEXT level: request, requestfinished,
    # requestfailed (plus workers/service workers where Playwright exposes them), and
    # writes one "request" event per finished or failed request. Async contexts: sizes()
    # is awaited in a task; pending tasks are flushed on context "close".
def wrap_new_context(browser) -> browser  # idempotent; patches new_context and new_page
    # proxy={"server", "username", "password"} passed per context is rewritten to
    # server=SCRAPESCOPE_AUTH_PROXY_URL (when a username is present, else SCRAPESCOPE_PROXY_URL),
    # username/password unchanged. Every new context is also instrument()ed.
def record_launch(browser) -> None        # one "launch" event per underlying browser (idempotent; round 4)
def launch(browser_type, **kwargs) -> Browser          # sync API
async def async_launch(browser_type, **kwargs) -> Browser  # async API
    # launch(proxy=proxy_settings() unless proxy given, **kwargs), record_launch, wrap_new_context.
```

Why the auth URL: Chromium sends proxy credentials only after a 407 challenge,
so per-context credentials would never reach the meter's main listener (which,
in `run`, accepts tokenless connections and injects the configured upstream
credentials). The auth listener answers 407 when no credentials are sent, so
Playwright presents the context's own username/password, which the meter then
passes through unchanged (section 3.3).

Clarifications recorded at integration (helpers role):

- `launch()`/`async_launch()` rewrite a caller-supplied `proxy` the same way
  `wrap_new_context` does (server = meter, credentials passed through) instead
  of keeping it; otherwise that browser would bypass the meter.
- `wrap_new_context` still rewrites proxies when `SCRAPESCOPE_PROXY_URL` is set
  but `SCRAPESCOPE_EVENTS` is not.
- `helpers.playwright.drain()` (async) and `DRAIN_TIMEOUT_S`: wait for pending
  async size lookups; the wrapped async `close()` calls it.
- Playwright on Chromium disables the HTTP cache (`Network.setCacheDisabled`)
  whenever a context or launch holds proxy or HTTP credentials.
  `proxy_settings()` without credentials keeps the cache (the meter injects the
  upstream credentials); per-context credentials cost the cache.
- Code that registers Playwright event handlers must pass fresh closures per
  object: Playwright caches its sync-or-async wrapper on the handler function.

Round 1 additions (helpers role):

- `is_multiplexed(sizes, header_names=None, status=None) -> bool`: True for an
  HTTP/2 or HTTP/3 response (a pseudo-header such as `:authority` among the
  request headers actually sent, or `responseHeadersSize == 0` on a response
  with a status). For such requests the helper writes `request_header_bytes`
  and `response_header_bytes` as null; `find` uses the same function to keep
  rebuilt header sizes out of its billed basis.
- Failed requests are written with `encoded_body_bytes` null.
- Unfinished requests: requests still in flight when a page navigates or closes
  get no Playwright event. The helper keeps the requests it saw start and
  writes those that never finished as failed with unknown sizes when the
  context or browser closes, or at interpreter exit (an `atexit` hook
  registered on first use) for contexts never closed. WebSockets still open at
  close are written too.
- `instrument(context)` records the context's browser as launched (once per
  browser). Round 4: `record_launch(obj)` is idempotent per underlying
  browser; a context counts as `context.browser` when Playwright exposes one.
  Playwright 1.63 does so for persistent contexts too (the earlier claim that
  a persistent context has no Browser object is false for 1.63), and
  `instrument(context)` records it, so `record_launch(context)` plus
  `instrument(context)` write one launch in either order. On versions whose
  persistent context has no Browser, `instrument` records nothing and
  `record_launch(context)` is what counts the launch.

Round 2 additions (helpers role, integrated by the verifier):

- Disk-cache candidates are held until the context shows wire headers, or
  decided at once when `response.server_addr()` is not the current meter (an
  entry cached during an earlier run), or decided at context close (cache hits
  for Chromium, network requests for other browsers). Service-worker script
  fetches are never cache candidates; DevTools reports worker and
  service-worker script bodies as 0.
- Per-context and launch `proxy=` servers are rerouted to the meter only when
  they match `SCRAPESCOPE_UPSTREAM_ID`, which `run` sets whenever an upstream
  is configured (`config.upstream_id(upstream.host, upstream.port)`; removed
  otherwise). Other servers are left alone with one warning, and their traffic
  shows as bypass. Without the variable (sizing mode, or outside `run`),
  every server is rerouted, with one warning when a process names two
  different ones.
- `launch()`/`async_launch()` take `webrtc_proxied_only: bool = False`; True
  adds `WEBRTC_PROXIED_ONLY_ARGS`
  (`--force-webrtc-ip-handling-policy=disable_non_proxied_udp`), the switch
  `find` always sets (`find.browser.FIND_CHROMIUM_ARGS` is the same tuple).

Event mapping: `frame` is `main` when `request.frame` is the page's main frame,
`sub` for other frames, `service_worker` when `request.service_worker` is set,
`worker` for dedicated/shared workers, else `other`. `sent_cookies` /
`sent_authorization` come from `request.all_headers()` key presence (never
values). `from_service_worker` from `response.from_service_worker`.
`from_cache` (Playwright exposes no direct flag; checked with Chromium 153): a
memory-cache hit reports `responseBodySize < 0` (body = -headers). A disk-cache
hit reports its full size and is recognised by carrying only the provisional
request headers (`all_headers()` names equal `request.headers` names: no
`Host`/`:authority` or other headers the network stack adds). The second test
is used only after the context has shown wire-level headers and while no route
or HTTP/proxy credentials are active on the page or context, because request
interception makes network requests look the same. Redirects and failed
requests are never cache hits. Cache hits are written with sizes 0.

Round 3 additions (helpers role, integrated by the verifier):

- `from_service_worker` is written false when the response shows wire-level
  request headers, or, under interception, has a server address: the
  Chromium warm-profile race, where the worker was not running and the
  network answered. Such an event is a network request with
  `encoded_body_bytes` null (DevTools reports 0) and the header sizes as
  reported. Worker-built and worker-fetched answers (no wire headers, no
  server address) keep sizes 0.
- Firefox and WebKit contexts: a cacheable response with
  `response.server_addr()` None is written as a cache hit with sizes 0
  (checked with Firefox 155 and WebKit 26.6). The Chromium provisional-header
  heuristic and the holding of candidates apply only to Chromium and to
  unknown browsers; Firefox/WebKit events are written at once, not held until
  close. This costs one `server_addr()` round trip per cacheable request in
  those browsers.

## 6. Attribution

```python
from scrapescope.attribution import read_events, attribute, EventsLog

@dataclass
class EventsLog:
    events: list[HelperEvent]
    dropped: int               # invalid, oversized or wrong-version lines (and lines past the cap)
    capped: int                # round 4: lines past MAX_EVENTS (1,000,000), also counted in dropped

def read_events(path: str | os.PathLike) -> EventsLog      # missing file -> empty log
# EventsLog.error: short reason (never the path) when the file exists but cannot be read;
# the runner turns it into a report warning.
def attribute(snapshot: MeterSnapshot, events: Sequence[HelperEvent], catalogs: Catalogs, *,
              units_override: int | None = None, events_dropped: int = 0,
              events_capped: int | None = None) -> AttributionResult
# round 4 (sec4-5): the runner passes events_capped=log.capped; attribute() warns when the cap
# was reached ("N helper event lines were not read: the reader keeps at most M events ...").
# Without it, the cap counts as reached when len(events) >= MAX_EVENTS. Repeated event strings
# are shared: about 0.5 KB per event, about 0.5 GB at MAX_EVENTS (docs/security.md).
# Round 4: attribute() canonicalises request and tunnel hosts (types.canonical_host) before
# matching, so bypass.hosts names addresses in the meter's spelling.
```

Algorithm (all byte figures on the with-CONNECT basis, so buckets sum to
`snapshot.totals().with_connect`):

1. `first_observation` = earliest `attach` ts; if there are no attach events,
   the earliest request event ts; None without events.
2. Network requests = `RequestEvent`s with `hit_network` (cache hits and
   service-worker-answered page requests are excluded; the worker's own fetch
   counts once).
3. Group target tunnels by host. For each host H:
   - If any network request has host H: every tunnel of H is `attributed`.
     Allocate `H.bytes_with_connect` over H's network requests in proportion to
     `reported_bytes` (by request count when all are 0), with a
     largest-remainder rounding so `sum(allocated_by_type.values()) ==
     H.bytes_with_connect` exactly. Scaling down (reported above tunnel bytes)
     is unlimited. Scaling up is bounded (round 1): the reported bytes may grow
     by an allowance of, per tunnel, its real and synthetic negotiation bytes
     plus `OVERHEAD_PER_TUNNEL_BYTES` (16,448 = 2 x 7,200 + 2,048; round 4,
     meas4-6: only for records with `opened_connection`, since a record that
     continues a kept provider connection set up nothing), plus
     `OVERHEAD_SHARE` (25%) of the reported bytes, plus `UNKNOWN_HEADERS_BYTES`
     (512) per request with unknown header sizes. Tunnel bytes beyond reported
     + allowance go to the type `unreported` (`UNREPORTED_TYPE`), which
     what-if figures and fixes ignore; a warning names hosts with at least
     `UNREPORTED_WARN_BYTES` (64,000) of it. A request event that claims the
     type `unreported` is filed as `other`. Hosts with a successful response of
     unknown body size (a Requests hook on a chunked body) are not bounded.
   - Otherwise classify each tunnel, first match wins:
     `background:<id>` when `catalogs.background_id_for(H)` matches (ONLY then);
     `before_attach` when `first_observation` is set and `opened_at <
     first_observation`; `preconnect_idle` when `first_observation` is set,
     the tunnel did not fail (round 3, meas3-8) and `payload_bytes_sent <=
     3072` and `payload_bytes_received <= 6144`; otherwise `unattributed`. A
     refused CONNECT (402/407/502, `failed:*`) of a host with no request thus
     goes to `before_attach` if it opened before the first observation,
     otherwise to `unattributed`. Without any helper events every non-catalogued
     tunnel is `unattributed`. An uncatalogued host is never background.
4. `hosts[]`: one `HostAttribution` per host with target or denied tunnels,
   sorted by `bytes_with_connect` descending then host; `buckets` holds a
   `BucketTally(tunnels, bytes)` per bucket name; `paths` only when events carry
   paths (top 20 by reported bytes).
5. `types[]`: per `resource_type` over attributed hosts: request count,
   reported bytes, allocated bytes (sum of allocated equals `buckets.attributed`).
6. `buckets`: run-level sums; `background` maps catalog id to bytes.
7. `non_target[]`: non-target tunnels grouped by host with the direct.json id.
8. Units: `units_override` gives `(N, "override")`. Otherwise Playwright
   main-frame navigation requests (`frame == "main" and is_navigation`)
   excluding 3xx responses give `"navigations"`; else hook request events
   excluding 3xx give `"requests"`; else `(0, "none")`.
   `low_sample_warning = count < 20`.
9. `success` (only when unit events exist): unit events with status 200-299 or
   304 and not failed; `rate = success / number of unit events`.
10. `browser_launches` = launch events. `bytes_before_first_navigation` =
    timeline bytes in buckets that END at or before the first unit event's ts
    (None without unit events); the bucket straddling t1 belongs to the first
    unit, so a load that fits in one bucket is not "before the first page"
    (changed at integration). `per_unit`: with unit timestamps t1 < t2 < ...,
    first unit = the remaining buckets ending at or before t2, rest = buckets
    ending after t2 (round 3, meas3-4: the step straddling the second unit's
    start goes to the rest, mirroring the t1 rule),
    `rest_units = n - 1`, `rest_mean_bytes = rest // (n - 1)` or None;
    `resolution_s` = the snapshot's. Approximate to one timeline bucket.
    `per_unit` is None, with a warning starting `PER_UNIT_WITHHELD_PREFIX`
    ("first unit vs the rest not shown"), when t2 - t1 is less than one
    timeline bucket; `bytes_before_first_navigation` is still given.
    Round 3 (meas3-5): for navigation units, a unit's timestamp is the start
    of its redirect chain: the first 3xx main-frame navigation event, in the
    same context, since that context's previous non-3xx navigation, each hop
    within `REDIRECT_CHAIN_MAX_GAP_S` (30 s).
11. `status_histogram`: network requests by `str(status)`, or `"failed"` when
    failed without a status.
12. Bypass: a network request with scheme http/https/ws/wss, a host that is
    not loopback (`localhost`, 127.0.0.0/8, `::1`), not failed-without-status,
    and (a) whose host appears in NO TunnelRecord of any route or status, or
    (b, round 1) that started more than `BYPASS_TIME_SLACK_S` (2 s) after every
    tunnel to its host had closed (tunnels still open count until the
    snapshot), or (c, round 1) whose host's reported bytes exceed
    `BYPASS_VOLUME_FACTOR` (1.5) x its tunnel bytes + `BYPASS_VOLUME_SLACK_BYTES`
    (65,536), WebSocket payloads excluded. Any such request sets
    `bypass.incomplete = True`; `hosts` (sorted, max 100) and `requests` count
    them. The banner reads "helpers or hooks reported traffic that the meter did
    not carry". The detector cannot see uninstrumented clients that bypass the
    meter; the report says so. Round 2: a `403` to a request that started after
    the budget tripped (the meter's own refusal, which records no tunnel) is
    not bypass. Round 3 (meas3-2): when a `firefox` or `webkit` launch event
    exists, Playwright-sourced request events are left out of the volume check
    (c); hook events still count.
13. `multi_page_context`: some context id (None counts as one context) has two
    or more navigation unit events.
14. `sources`: sorted distinct sources of request events. `events`: counts per
    kind plus `dropped`. `warnings`: dropped events, fewer than 20 units, no
    helper events ("no helper events: per-type figures unavailable; buckets
    only"), bypass, internal errors in the snapshot. Round 3: a Firefox or
    WebKit launch adds a warning starting `NON_CDP_WARNING_PREFIX` ("per-type
    figures for Firefox are unverified: ...", naming WebKit when launched).

## 7. find

```python
from scrapescope.find import run_find, render_find_text, classify_challenge, BrowserUnavailableError

class BrowserUnavailableError(RuntimeError): ...   # Playwright or Chromium missing -> CLI exit 3
    # message starts "Playwright is not installed" (package) or "Chromium could not be started"

async def run_find(url: str, values: Sequence[str], *, proxy_url: str, catalogs: Catalogs,

                   headless: bool = True) -> FindResult
    # added at integration (find role):
    #   browser_args: Sequence[str] = ()        tests only (e.g. the fixture SPKI allow-list)
    #   abort_check: Callable[[], str | None]   polled every 0.25 s while navigating; a non-empty
    #                                           string ends the load with status "error" and that reason
    # added in round 2 (integrating verifier):
    #   before_verify: Callable[[], None]       called once, after the browser closed and just before
    #                                           the --verify request (the CLI splits its meter: line there)
    # added in round 3 (sec3-4):
    #   meter_reply_check: MeterReplyCheck | None   confirms X-Scrapescope-Error replies against the
    #                                           meter's records; build it with
    #                                           meter_reply_check_from_snapshot(forwarder.snapshot)

                       body_text: str | None, catalogs: Catalogs) -> ChallengeResult
def render_find_text(result: FindResult, *, show_code: bool = True) -> str
def meter_reply_check_from_snapshot(snapshot_fn: Callable[[], MeterSnapshot]) -> MeterReplyCheck   # round 3
# find.render.share_line(result) -> str | None   (round 3) the terminal's share line, also used by reports
```

Behaviour:

1. Launch headless Chromium (Playwright, imported lazily) with
   `proxy={"server": proxy_url}` and the default user agent (no spoofing).
   Round 2 (sec2-1): always with `FIND_CHROMIUM_ARGS`
   (`--force-webrtc-ip-handling-policy=disable_non_proxied_udp`), so WebRTC
   may use proxied connections only: no STUN or UDP from this machine and no
   local-address leak. It covers find's own browser only.
   One context, one page, `goto(url)` then a bounded wait for network quiet; at
   most one retry. `ca_file` (tests only, from `SCRAPESCOPE_TEST_CA`) sets
   `ignore_https_errors=True` for the browser and `verify=ca_file` for httpx.
2. Run `classify_challenge` on the main document first (status, headers,
   `Set-Cookie` names, first 64 KiB of the body). On `blocked`: status
   `"blocked"`, no search, coverage 0, verify `not_tested` with reason
   `"blocked"`, terminal line `blocked; cannot search (challenge: <vendor name>)`.
   Never "not found" for a challenge page. Round 1: sub-responses are
   classified too: XHR, fetch, eventsource, `other`, iframe documents, and any
   non-2xx or 202 response (2xx scripts and stylesheets are not, since vendor
   scripts contain challenge markers). A challenged sub-response is not
   searched, is counted under the coverage reason `challenge`, and a warning
   names the vendor, so a "not found" mentions the challenge.
3. Read text bodies (`text/*`, JSON and `+json`, JavaScript, XML) from the
   whole context, frames and workers included, under `body_cap_bytes`. Count
   skips by reason in `Coverage.skipped` using the keys of
   `COVERAGE_SKIP_LABELS` (`over_cap`, `evicted`, `no_session`, `websocket`,
   `binary`, `failed`, `no_body`, `challenge`, `other`).
4. Search each value in memory with variants, then discard bodies. Variant ids
   (used in `match_kinds` as `variant:<id>`): `json-escape`, `html-entity`,
   `number-format` (thousands separators, decimal comma/point, trailing zeros),
   `space-normalized` (U+00A0 and U+202F), `tag-stripped` (HTML visible text,
   split tags), `case-insensitive`, and `substring` (round 1; numeric values
   only, the weakest kind). Round 1 details:
   - JS/JSON escapes are decoded in HTML documents, inline scripts, JS and JSON
     bodies: HTML-safe `\u0026`/`\u003c` forms (Next.js
     `htmlEscapeJsonString`, Rails, PHP `JSON_HEX_*`), `\xNN`, `\'`,
     `\u{X}`, surrogate pairs, double-escaped strings (Next.js RSC flight) and
     HTML entities inside JSON strings.
   - A numeric value may carry one currency symbol (Unicode Sc, optionally
     after up to three capitals as in `US$`) or ISO 4217 code before or after
     the number; the bare number is then also matched (`variant:number-format`)
     and the value counts as numeric-only for `short_value_warning`.
   - Numeric values need digit boundaries for `exact` (`51.77` is not exact
     inside `151.77` or `51.775`); such hits are `variant:substring`.
   - Variant matching covers the whole JSON body; `MAX_JSON_NODES` (200,000)
     limits only the listing of `json-key:` locations.

   Round 2 (find area):
   - Digit boundaries apply to ANY value whose first or last character is a
     digit, not only numeric values (`22 available` is not exact inside
     `122 available`). `variant:substring` covers those values too and never
     counts as found: it is excluded from `values_matched`, `all_values`, the
     status and exit code, and from verify's `replays: yes`. A response with
     only weak hits is not listed.
   - `number-format` no longer reads `1,000` (three zeros after one separator)
     as 1. Its decimal zeros never form a 3-digit group (`1000` is not in
     `1,000,000`; `4.5` is not `4,500`). It does not continue space- or
     apostrophe-grouped numbers (`12345` is not in `12 345 678`). It keeps a
     minus sign and leading zeros (`-42` is not `42`, `007` is not `7`).
     Privacy checks still drop paths holding the magnitude (for example
     `2134` for `02134`).
   - HTML entities are decoded in JSON and JavaScript bodies even without any
     backslash, and `json-key:` locations are reported for entity-encoded
     leaves.

   `locations` examples: `document`, `xhr`, `fetch`, `script`,
   `embedded:next-data`, `embedded:ld-json`, `json-key:<dotted.key.path>` (keys
   limited to `[A-Za-z0-9_.$@\[\]-]`), `html-text`. Paths and `json-key:`
   locations are dropped when they contain a value in any searched form (other
   number formats, a bare digit run or array index equal to the number,
   repeated percent-encoding, HTML entities). Round 2 labels: `script-text`,
   `css-text`, `xml-text`, `svg-text`, `plain-text` (a body without finer
   locations) and `json-text` (a JSON match outside every leaf, for example in
   a key). Round 1: `FindMatch.locations_by_value`
   holds, per value, the locations of that value (at most 10 each);
   `locations` stays the merged per-response list with the base labels first.
5. Rank (round 1 order): responses containing ALL values first, then more
   values matched, then fewer `variant:substring` hits, then network responses
   before copies served by a service worker or the HTTP cache, then ascending
   `billed_basis_bytes = encoded_body_bytes + response_header_bytes +
   request_header_bytes + (TLS_HANDSHAKE_ESTIMATE_BYTES if https else 0)`.
   On HTTP/2 and HTTP/3 (`helpers.playwright.is_multiplexed`), both header
   fields are 0 and `FindMatch.multiplexed` is true: the encoded body already
   includes the response header frames, and the rebuilt HTTP/1.1 request-header
   size is left out. Keep at most 20 matches. A value, stripped (and without a
   currency affix), that is shorter than 5 characters or consists only of
   digits, spaces and `.,` is short (the smallest match is then often a beacon
   or an ID). Round 2 (ux-1): the warning names the value index ("value 2 is
   short or numeric-only: ..."; `core.short_value_note`), and it and
   `short_value_warning` are left out when nothing was searched (status
   `blocked` or `error`) or when the top match also contains, as itself, a
   value that is not short.
6. Flags per match (`FindFlags`): `sent_cookies`, `sent_authorization` (header
   presence in the request actually sent), `random_query_token` (any query value
   that looks random: JWTs and UUIDs in any case, 16+ hex, 20+ base64url with
   both cases, 20+ id characters in either case with at least 5 letter/digit
   alternations, 16+ mixed letters and digits; round 1 also sets it for a URL
   path segment that is a JWT, contains a UUID, or is 24+ hex; round 2: path
   segments exactly when `types.is_path_token_segment` says so, which adds
   32+ base64url, and `;name=value` path parameters such as `;jsessionid=`;
   parameter names that look like a session or signature, matched per word:
   `token`, `session`, `sid`, `sig`, `auth`, `csrf`, `xsrf`, `hmac`, ..., plus
   `__token__`, `hdnts`, `policy`, `key-pair-id`, `cfid`, `cftoken`,
   `jsessionid`, `phpsessid`, `aspsessionid*`, `api_key`, with any non-empty
   value; and tokens embedded in compound values: a JWT anywhere, a 16+ hex
   run, random parts after splitting on `~ = : , . ; | !`), `third_party`
   (last two host labels differ from the target's; heuristic without a public
   suffix list), `non_get`, `sent_token_header` (round 4 find review: a
   credential- or token-like request header, presence only).
7. Code eligibility: GET, 2xx, no cookies, no Authorization, no random-looking
   token. Eligible matches get `StarterCode` (terminal only): `curl
   --compressed '<url>'` and an httpx snippet (whose proxy comment names
   `HTTPS_PROXY` for https URLs and `HTTP_PROXY`/`http_proxy` for http URLs,
   and which asks for `httpx[brotli,zstd]` when the browser received br or
   zstd). Ineligible ones print exactly: `not emitted: this response depends on
   session or anti-bot state; use the page or the site's official API, and
   check its terms` and set `code_ineligible_reason` to a short reason (`sent
   cookies`, `sent authorization`, `random-looking query token`,
   `random-looking token in the path`, `not a GET`, `status <n>`). Amended by
   item 15 below (round 4 find review): that text is for session
   state only, other reasons have their own text
   (`heuristics.not_emitted_text`), and while some listed match holds every
   value only such a match gets starter code.
8. `--verify`: exactly ONE cookie-less `httpx.AsyncClient(proxy=proxy_url,
   verify=ca_file or True, follow_redirects=False)` GET of the top eligible
   match with `User-Agent: config.USER_AGENT`. `replays = "yes"` when the status
   is 2xx and the body still contains every value that match contained (same
   variant search), `"no"` otherwise (`reason` `status <n>` or `value missing`),
   `"not_tested"` when not requested (`not requested`), no eligible match
   (`no eligible match`) or blocked. Never replay captured cookies, tokens or
   headers. Round 1: `VerifyResult.received_bytes` is the body bytes received
   (before decompression) and `replay_billed_basis_bytes` the replay's body +
   header bytes + the match's TLS estimate; a warning compares it with the
   browser's billed basis when it is more than 1.2 times larger. Transport and
   client errors are `not_tested` with `request failed (<Class>[, <errno>|SSL])`,
   including `request failed (InvalidURL)` and any unexpected client exception.
   Round 2 (sec2-3): the replay sends `Accept-Encoding: gzip, deflate` and
   decodes the body itself with a bounded zlib decoder
   (`decompressobj().decompress(data, max_length)`); the size cap applies to
   the raw bytes and to the decoded bytes. A response with more than one
   content coding, or with br, zstd or another coding, is `not_tested` with
   reason `unsupported content encoding (<codings>)`; a corrupt stream gives
   `(<coding>, corrupt)`. The replay's Accept-Encoding therefore differs from
   the starter code's when brotli or zstandard are installed; the replay
   warning names what it accepted.
9. Privacy: `FindResult` never contains the values. `path` fields hold
   `clean_path` output and are set to None when the path (raw or
   percent-decoded, case-insensitive) contains any value. Full URLs appear only
   in the terminal-only fields `target_url`, `match_urls` and `starter_code`.
   Never say "the page computed the value".
10. `status`: `found` (at least one match), `not_found` (coverage line
    `not found in N inspected responses; skipped: ...` from
    `Coverage.summary(False)`), `blocked`, `error` (navigation failed; warning
    says why without the URL query). Round 2:
    - When the main document is the meter's own reply (`http://` only:
      `X-Scrapescope-Error` plus a `scrapescope:` body), the status is `error`
      (exit 5), with the warning `page load failed: the main document is the
      meter's own reply (status N, X-Scrapescope-Error: code), not the site's:
      <reason>; cannot search`; for `private-address` the reason names
      `--allow-private-targets`. Round 4 (sec4-2): only when the refused
      address is the target's own host and port as typed (any spelling of the
      same address, compared through `find.browser.endpoint_host`); a DNS-name
      target adds `core.PRIVATE_NAME_CAUTION` ("only if you expect this name
      on your own network: a public name that resolves to a private address
      can be a DNS-rebinding attack"), and a main document refused after a
      redirect elsewhere gets `core.PRIVATE_REDIRECT_NOTE` ("the target
      redirected to a private or local address ...; use
      --allow-private-targets only for a site you trust"). Sub-requests the
      meter answered are skipped as `failed`, with a warning; for
      `private-address` it never advises the option: a sub-request gets
      `core.PRIVATE_SUBREQUEST_NOTE` ("the page asked for a private or local
      address and the meter refused it to protect this machine's network;
      --allow-private-targets would let the page reach it, so use it only for
      a page you trust"), and a later request to the target's own host and
      port `core.PRIVATE_OWN_NAME_NOTE` (DNS rebinding or split DNS). An
      `http://` site can still imitate a meter reply; an `https://` response
      never counts as one.
    - After a failed navigation, `abort_check` is asked again; its reason
      replaces the net error, which is shown in parentheses, and there is no
      retry. The CLI's check (`runner._find_abort_check`) returns a reason for
      a budget trip, an upstream 407, SOCKS5 auth failure or unreachable
      upstream, and, for `https://` targets, a CONNECT tunnel to the target's
      own host and port with status `failed:private_address`, `denied` ("the
      host matches --deny-host or --deny-catalog") or `failed:self_loop`.
      Round 4: hosts are compared canonically (`types.canonical_host`, sec4-3),
      so `https://[::ffff:127.0.0.1]/` matches the record for `127.0.0.1`.
      For `failed:private_address` (sec4-2) the reason is "the meter refused
      the target's private or local address (...); pass
      --allow-private-targets to load it" for the first connection to an IP
      literal, `runner._TARGET_NAME_PRIVATE` (the option with the rebinding
      caution) for a DNS name, and `runner._TARGET_REBOUND` ("a later
      connection to the target's own name was refused as a private or local
      address although the page loaded from it (DNS rebinding or split DNS);
      use --allow-private-targets only for a site you trust") when an earlier
      connection to the target succeeded; the same reason becomes `not sent:
      <reason>` when the check fires before `--verify`. `find` keeps up to 300
      characters of an abort reason (`browser.ABORT_REASON_MAX`; 80 before
      round 4, which cut the option off).
      A tunnel failure to a loopback or private literal or to `localhost` is
      not retried and adds a hint naming `--allow-private-targets`.
    - A warning `not found: value N; only responses of the initial page load
      were inspected; content loaded later by scrolling, clicking or timers is
      not covered` names every value in no inspected response (as itself).
      `FindResult.missing_values` (terminal only) holds their 0-based indices;
      a `found` result with any exits 6 (section 13).
11. Additions recorded at integration: responses served by a service worker
    rank after network responses with the same all-values status and are not

    lists `ERR_UNSAFE_PORT`, `ERR_NAME_NOT_RESOLVED`, `ERR_INVALID_URL`,
    URL-scheme errors, `ERR_BLOCKED_BY_*`, `ERR_SSL_VERSION_OR_CIPHER_MISMATCH`,

    `FindMatch.content_encoding` records the matched response's

    untrusted pages) and falls back to no sandbox, with a result warning, only

    `scrapescope find: <host/path>  (N values)`, the coverage line, a summary

    gzip or deflate: the --verify replay moved about X B body and headers,
    more than this page load` (or `as much as`), followed by ` (see
    warnings)` when the replay warning exists, `not a saving until
    --verify replays it`, `not a saving: the --verify replay failed (...)`,
    `not a saving yet: the --verify replay was not tested (...)` or `... was
    not sent: <reason>`, `no saving: this one response is the whole page
    load`. The share is shown only for a code-eligible network response whose
    figures fit (at most 100%); an ineligible top match gets `share of this
    page load: not shown for rank N (<why>)`. Then per match a table row
    (rank, billed-basis, values, status, type, method, flags, match kind or
    `mixed` when the kinds differ), the host+path shortened in the middle so
    the file name stays, one line per value (`value i: <kind> in <locations>`),
    the response-level labels and Content-Encoding; a note for multiplexed
    matches; starter code or the not-emitted line; the verify result (left out
    when nothing was found and --verify was not requested); and warnings. All
    strings through `safe_text`. Round 2: rows that share host and path add
    `?<query>` (shortened), or `?(query <hash>)` for a row with a random-token
    flag; "also eligible:" lists one URL line per rank (round 3, ux-r3-1:
    after a blank line, as `also eligible (other responses that would get
    starter code):` at the outer indentation, so it is not copied with the
    code); a weak per-value line
    reads `(only inside a longer number; not counted)`; the `not found: value
    N; ...` warning is printed under the coverage line (it is also in
    report.json warnings).
13. Round 1 fields (report.json `find[].matches[]`, all optional in the
    schema): `content_encoding` (string or null), `multiplexed` (bool),
    `locations_by_value` (list of lists); `find[].verify.replay_billed_basis_bytes`
    (int or null). The coverage reason `challenge` is in the schema's
    `skipped` property names.
14. Round 3 additions (find area, integrated by the verifier):
    - `page_reported_bytes` leaves out responses served by a service worker
      or the HTTP cache (find3-11).
    - `meter_reply_check` (sec3-4): an `X-Scrapescope-Error` reply counts as
      the meter's own only when the meter's records hold it; unconfirmed
      look-alikes are searched as the site's responses and named in a
      warning. `runner.find_command` passes
      `meter_reply_check_from_snapshot(fw.snapshot)`. Round 4 (sec4-3): hosts
      are compared in canonical form on both sides through
      `find.browser.endpoint_host` (`canonical_host(clean_host(host))`), so
      `[::ffff:127.0.0.1]` and `::ffff:7f00:1` confirm a record for
      `127.0.0.1`. Round 4 (ux4-3): a forged header on the main document gives
      one warning ("the main document carried X-Scrapescope-Error: <code>
      although the meter did not refuse or fail this request: the site sent
      the header itself; searched as the site's response"); the aggregate
      "N responses carried ..." warning counts only the other responses.
    - Round 4 (meas4-5): for plain `http://` responses, `request_header_bytes`
      leaves out the proxy-hop headers Chromium sent to the meter
      (`Proxy-Connection`; `Proxy-Authorization` after a 407), as the
      Playwright helper does.
    - Code eligibility has a new reason `sent a token header` (credential- or
      session-like request header names, or `x-` headers with random-looking
      values; presence only; `heuristics.is_token_header`) and a
      `token-header` flag in the terminal table.
    - `--verify` target (`heuristics.select_verify_target`): the top eligible
      match, or a higher-ranked match ineligible only for sent cookies or a
      token header (a replay candidate) when the top eligible match holding
      the same values is more than 2x its size (body and headers). A
      candidate gets starter code only when its replay says yes.
    - New verify reasons: `not sent: <reason>` (abort_check fired: budget
      tripped, upstream failed), `the meter answered itself (<code>)`, `the
      proxy asked for credentials (status 407)`, `gateway error (status
      502|504)` (all `not_tested`), and `replay exceeded N s` (one overall
      deadline). Any Content-Encoding text in reasons and warnings is reduced
      to validated coding tokens.
    - The curl starter command gets `--globoff` when the URL holds `[ ] { }`.
    - `decode_body` never raises for a site-chosen charset; undefined, `idna`,
      `punycode`, `unicode-escape` and `utf-7` labels are read as UTF-8. An
      unexpected ValueError after argument validation surfaces as
      `find.core.FindInternalError` (a RuntimeError), so the CLI keeps the
      meter report.
    - Number matching: space, NBSP, NNBSP, thin-space and apostrophe group
      separators are number boundaries only when no 3-digit group continues
      the number; commas between array or list elements are element
      boundaries; a parsed JSON leaf equal to the value counts; letter
      currencies (`zł`, `kr`, `Kč`, `Ft`, `lei`, `руб.`, `R`, `Rs`...) are
      currency affixes. Location labels use the same boundaries.
    - Round 4 (hon4-1), number formats never read a different number: one
      kind of thousands separator per number, and the decimal separator must
      differ from it (`1,234.567` is not 1234567); a value without a sign is
      not found right after a minus sign (`42` is not in `-42`, U+2212 `42`
      or `1e-42`; `ABC-42` and `2020-2024` are hyphens and still match); for
      a whole-number value (`1994`, `1 994`, `5,000`, `1994.00`) a single
      thousands dot such as `1.994` counts only next to a currency (`1.994
      EUR`, `EUR 1.994`, `kr 1.994`, `1.299,-`), while two dot groups or a
      following decimal comma need none. In a parsed JSON body, number
      tokens are compared as numbers over the whole body (`.` is a decimal
      point, `,` separates array elements). Limits: in JavaScript, CSS and
      JSON embedded in HTML, `[1,994]` still reads as 1994; a German `1.994`
      without a currency is no longer matched for 1994 (a deliberate false
      negative). The privacy matcher (`contains_any_value`) stays loose.
    - When the main document status is 400 or more, the not-found note names
      the status (and any vendor with firing signals) instead of the
      scrolling/clicking hint (`core.error_document_note`).
15. Round 4 find review (find-r4-1 ... find-r4-8):
    - Starter code (`FindResult.starter_code`, and what the terminal prints):
      while some listed match holds every value, only such a match gets
      starter code, also after a candidate's replay said yes. Eligible
      matches that lack a value are listed with `(holds N of M values)`,
      under "also eligible" after the code, or under "eligible but missing a
      value (no starter code while a response holds every value):" when no
      match with every value is eligible. When no match holds every value,
      the starter-code heading and the verify line add `holds N of M values
      (value K is not in it)` (`render.holds_text`).
    - Not-emitted lines by reason (`heuristics.not_emitted_text`): the
      session/anti-bot text only for `sent cookies`, `sent authorization`,
      `sent a token header` and the random-token reasons; `not a GET` reads
      `not emitted: starter code covers GET only; the request body and
      headers are not reproduced`, `status <n>` `not emitted: the response
      had status <n>`, `status unknown` `not emitted: the response status is
      unknown`, `served by a service worker` `not emitted: the page's service
      worker answered; the network response may differ`.
    - `FindFlags.sent_token_header` (report.json `flags.sent_token_header`,
      optional in the schema) records the token header whatever the
      eligibility reason and after a yes replay; the terminal shows
      `token-header` from it, the report `sent a token header`.
    - Report rendering: the find table's values column is `all N/M` or `some
      N/M`; the match column is the one shared kind or `mixed: 1
      number-format, 2 exact` (a weak hit `substring (not counted)`); the
      verify line is the terminal's (`render.verify_line` on the rebuilt
      entry), naming the replayed rank; `_fmt.verify_hosts` uses
      `render.replayed_match` (the same `select_verify_target` choice), so a
      replayed candidate that said no is the replay's host.
    - Number matching: for a numeric value in a parsed JSON body the exact,
      escape, entity, space and case tests search the body with its number
      tokens masked, and a token equal to the value as typed is `exact`
      (`1,299` is not in `[1,299]`, `12,5` not in `[12,5]`). A value
      starting with an ASCII `-` or `+` and a digit is not matched where that
      character follows a letter, digit or underscore (`search.sign_not_joined`:
      `-42` is not in `ABC-42` or `1e-42`), in the exact test and, for `-`,
      the `number-format` variant. The number formats read a leading `+` as no
      sign, so `+42` still matches the `42` in `ABC+42` as `number-format`.
    - `--verify` with no match at all is `not tested (nothing matched)`; `no
      eligible match` is kept for results with matches but no eligible one.
    - The `meter:` line counts `failed:client_closed` tunnels separately (`N
      closed by the browser before the tunnel opened`), not as failed.

## 8. Catalogs

Package data under `src/scrapescope/catalog/`: `background.json`,
`challenges.json`, `direct.json`, each with a string `version` (for example
`"2026.09.23"`), loaded with `importlib.resources`.

```python
from scrapescope.catalog import load_catalogs, load_documents

```

Formats (validated by `types.Catalogs.from_documents`; extra keys ignored, so
an `"attribution"` or `"notes"` key is allowed at top level):

```jsonc
// background.json
{"version": "2026.09.23", "entries": [
  {"id": "optimization-guide", "hosts": ["optimizationguide-pa.googleapis.com"],
   "component": "Chromium optimization guide model downloads",
   "evidence": ["https://news.ycombinator.com/item?id=41593410", "..."],
   "security_tradeoff": "...", "last_verified": "2026-09-23"}]}
// challenges.json
{"version": "2026.09.23", "attribution": "Some patterns adapted from is-antibot (MIT) ...",
 "vendors": [{"id": "cloudflare", "name": "Cloudflare", "source": null,
   "signals": [{"type": "header", "name": "cf-mitigated", "pattern": "^challenge$",
                "statuses": [], "strength": "challenge"}],
   "docs": ["https://developers.cloudflare.com/cloudflare-challenges/challenge-types/challenge-pages/detect-response/"]}]}
// direct.json
{"version": "2026.09.23", "entries": [
  {"id": "openai", "hosts": ["api.openai.com", "*.openai.azure.com"], "reason": "LLM API"}]}
```

Ids: `[a-z0-9][a-z0-9_-]{0,63}`, unique per file. Host globs per section 2.1.

Round 1 evidence rules, enforced by `catalog.check_documents` (the strict
check the tests run on the packaged files):

- background.json entries carry `host_evidence: {host glob: [urls]}` with an
  entry for every host glob, and every URL there is also in `evidence`, so a
  glob cannot ride on another host's source. `credits` name people or reports
  whose URL is in `evidence`.
- challenges.json signals carry their own `sources` (https URLs of pages that
  contain the signal) and an optional `note` (how the rule differs from its
  source, for example an added status restriction).

Signal semantics (implemented by `find.classify_challenge`):

| type | fires when |
|---|---|
| `header` | response header `name` (case-insensitive) is present and, if `pattern` is set, its value matches `re.search(pattern, value, re.I)` |
| `cookie` | a `Set-Cookie` in the response has a cookie name matching the glob `name` (`fnmatch.fnmatchcase`), and, if `pattern` is set, its value matches |
| `status` | the status is in `statuses` (`name`/`pattern` unused) |
| `body` | `pattern` matches (`re.search`, `re.I`) the first 64 KiB of the decoded text body |

For every type, a non-empty `statuses` list additionally requires the status
to be in it. `strength: "challenge"` signals make the response `blocked`;
`strength: "vendor"` signals only name the vendor. The result's `vendor_id` is
the vendor of the first firing challenge signal, else of the first firing
vendor signal; `signals` lists `"<vendor_id>:<type>:<name or signal index>"`.
Signals that also fire on ordinary pages (for example Cloudflare's
`/cdn-cgi/challenge-platform/` script, or bot-management cookies) must be
`vendor` strength or be restricted with `statuses`.

Required content (every entry with at least one evidence or docs URL):

- background.json: `optimizationguide-pa.googleapis.com` (credit NodeMaven's
  finding, measured 2026-08-19 and published by 2026-08-25, of about 43 MB in
  a fresh profile, intermittent across idle windows, and the Skyvern postmortem discussed at
  https://news.ycombinator.com/item?id=41593410); Chrome component and
  extension update hosts `clients2.google.com`, `update.googleapis.com`,

## 9. Model: costs and what-if

```python
from scrapescope.model import compute_cost, compute_what_if, BLOCKING_CAVEAT, CACHE_CAVEAT

BLOCKING_CAVEAT = "blocking can break extraction or attract anti-bot scrutiny; compare a second run"
CACHE_CAVEAT = "cache loss not modelled"

def compute_cost(totals: Totals, units: UnitsInfo, success: SuccessInfo | None, *,
                 rate: float, gb_unit: GbUnit) -> CostInfo
def compute_what_if(attribution: AttributionResult, totals: Totals, catalogs: Catalogs) -> list[WhatIf]
```

- `compute_cost`: `with_connect = totals.with_connect / unit_bytes(gb_unit) *
  rate`, same for `without_connect`; `per_1000_units = with_connect /
  units.count * 1000` when `units.count > 0`; `per_1000_successes` likewise when
  `success` and `success.count > 0`; `rate_unit` is `"USD per GB"` or
  `"USD per GiB"`; round to 6 decimals. Only called when `--rate` is given.
  There is no default rate anywhere.
- `compute_what_if`:
  - `block-images-media-fonts`: `bytes_saved` = allocated bytes of types
    `image`, `media`, `font`; emitted when > 0; caveats `[BLOCKING_CAVEAT]` plus
    `CACHE_CAVEAT` when `attribution.multi_page_context`.
  - `deny-background-catalog`: `bytes_saved` = sum of `buckets.background`;
    emitted when > 0; caveats: the security trade-off of the catalog entries
    involved and "compare a second run".
  - `share = bytes_saved / totals.with_connect` (0 when the total is 0), basis
    `allocated`.

(`TunnelRecord.opened_connection`), not records, so a keep-alive plain-HTTP

## 11. Report

```python
from scrapescope.report import (build_report, render_text, render_html, validate,
                                write_report, load_report, gate, load_schema, ReportError)

class ReportError(Exception): ...   # unreadable, not JSON, or invalid report -> CLI exit 2

def build_report(*, snapshot: MeterSnapshot, attribution: AttributionResult, catalogs: Catalogs,
                 options: ReportOptions, find_results: Sequence[FindResult] = (),
                 warnings: Sequence[str] = ()) -> dict
def render_text(report: dict) -> str
def render_html(report: dict) -> str
def validate(report: dict) -> list[str]          # [] when valid against schema.json
def write_report(report: dict, json_path, html_path=None) -> None   # atomic (temp file + os.replace)
def load_report(path) -> dict                     # raises ReportError; validates
def gate(report: dict, fail_on: Iterable[str]) -> int   # "budget" -> 86 if budget.tripped; "bypass" -> 87 if incomplete; 86 wins; else 0
def load_schema() -> dict
def write_html(report: dict, html_path) -> None    # added at integration: atomic, mode 0600 (report --html)
```

Files are created with mode 0600 (reports name the hosts a job contacted).
`write_report` raises `ReportError` for an invalid report (a builder bug; the
CLI exits 88); `load_report` raises `ReportError` (CLI exit 2).

`build_report` calls `snapshot.totals()`, `model.compute_cost` (only when
`options.rate` is set), `model.compute_what_if`, `snippets.generate_fixes`, and
assembles the dict defined by `report/schema.json` (section 11.1). It must:

- sanitise every string (`clean_host`, `clean_path`, `safe_text`, `safe_code`)
  and cap list lengths (hosts 10,000, warnings 200, matches 20 per find);
- include paths (hosts[].paths, find target and match paths) only when
  `options.keep_urls`; never query strings;
- with `options.redact_hosts`, replace every host field (hosts, non_target,
  budget event hosts and top_hosts, bypass hosts, find target and match hosts)
  by `catalog:<id>` when it matches a background or direct catalog entry, else
  `redacted:<first 12 hex of HMAC-SHA256(key, host)>` with a random 32-byte key
  per report that is never stored (stable within a report, unlinkable across
  reports); drop paths in that mode;
- never include bodies, query strings, cookies, header values, credentials,
  the upstream host or port, the command line, environment values or find values;
- add warnings: sizing mode ("sizing mode: no upstream; the with-CONNECT figure
  is estimated; exit location, blocking and retries of a real upstream are not
  reproduced"), budget trip with heaviest hosts, incomplete run, low unit count,
  and pass through `attribution.warnings` and the caller's `warnings`.

`render_text`: plain text, no colours, clearly labelled sections: header (tool
version, command, mode, unit, start/end), totals with and without CONNECT
(`tunnel-measured`, `estimated` in direct mode), tunnels and failed tunnels,
budget and budget events, units and per-unit figures (with the < 20 warning),
hosts table (top 20), buckets, types (`allocated`), non-target hosts, find
summaries, what-if, fixes, cost (`estimated billable transfer`), warnings, and
an `INCOMPLETE` banner when a bypass was detected. States that figures are not
a bill. Every string through `safe_text`.

`render_html`: one self-contained document, tables only, no scripts, no
external resources; a CSP meta tag `default-src 'none'; style-src
'sha256-<hash of the single inline <style>>'; img-src 'none'; base-uri 'none';
form-action 'none'`; every string `html.escape(..., quote=True)` after
`safe_text`.

Round 1 additions:

- `build_report` returns a `report._fmt.GeneratedReport` (a dict subclass).
  Renderers show the stored fix code only for such reports. Any other dict (a
  report read from a file, or built by hand) is untrusted: fix title, code and
  caveats are rebuilt from the id with `snippets.regenerate_fix`, and the
  renderers say so. Round 3 (data-r3-1): the detection is rebuilt too, from
  the report's own figures, and the renderer note reads "titles, detections,
  code and caveats are rebuilt by this scrapescope from each fix id and the
  file's own figures. Code and text stored in fixes are never shown." The schema's
  `fixes[].id` is an enum of the six generated ids, so a file with another id
  fails validation (exit 2).
- find reports: `browser_launches` = 1 per find result, `units.low_sample_warning`
  is false, the text rendering has a "Page load (find)" section instead of
  units, the page load's tunnels are labelled "find page load" instead of
  "unattributed", and the find section prints the terminal's own share line
  (`find.render.share_line`) and, since the round 4 find review, its verify
  line (`find.render.verify_line`) on the entry rebuilt from the report.
- run reports: "status (network requests; failed = no response)" (round 2
  label), "not network requests: N request event(s): HTTP-cache hits,
  service-worker answers, and requests answered or stopped before the network
  (route.fulfill, route.abort, browser blocks such as mixed content)" (round
  2; it replaced "served without the network"), "browser launches: not
  recorded" when browser request types exist without a launch event, the
  per-unit withholding note, the `unreported` type explained under resource
  types, and what-if lines that read "would remove about X (Y% of this run,
  modelled)". The budget note appears only when a budget is set.

Round 2 additions:

- `report.dumps` (used by `scrapescope report FILE --format json`) also
  rebuilds a report file's fixes from their ids (title, code and caveats
  regenerated), so no output format presents a file's own code as

- find reports: the "top match" share uses the same basis and top match as

- Warnings when every tunnel (or at least half of four or more) failed:
  `every tunnel failed (<reason> xN): <hint naming $VAR>` (the runner's

- Costs (`_fmt.money`): cents from $1 up, three significant digits below

Round 4 additions:

### 11.1 report.json v1 (`src/scrapescope/report/schema.json`)

JSON Schema draft 2020-12, `additionalProperties: false` on every object, so a
stray field fails validation. The schema uses only these keywords, which the
built-in validator must support: `$schema`, `$id`, `$ref` (to `#/$defs/...`),
`$defs`, `title`, `description`, `type` (string or list, `integer` excludes
booleans and non-integral floats, `number` excludes booleans), `const`, `enum`,
`properties`, `required`, `additionalProperties` (bool or schema),
`propertyNames`, `items`, `maxItems`, `minimum`, `maximum`, `minLength`,
`maxLength`, `pattern`. Keywords apply only to instances of their type (so
`properties` on a `["object", "null"]` schema ignores null). Every `pattern` is
anchored `^...$`; evaluate it so that a trailing newline does not match (for
example `re.fullmatch(p[1:-1], s)` for `^...$` patterns).

Top-level fields (all required, except the two optional round-2 diagnostics
fields `tunnel_failures` and `accept_limit_errors`, which the builders always
write; older reports without them still validate). The schema's `$id` is
`urn:scrapescope:report:v1` (round 2, honest-4): a non-resolvable identifier,
never a URL under a namespace the project has not reserved.

## 12. Runner and CLI

`scrapescope.cli.main(argv: Sequence[str] | None = None) -> int` parses
arguments (argparse; usage errors exit 2) and dispatches to `scrapescope.runner`.
`python -m scrapescope` and the `scrapescope` console script call it.

### 12.1 Command line

```text
scrapescope --version
scrapescope run    [common] [--upstream-from-env VAR | --direct] [--env-all]
                   [--units N] [--keep-events] [--fail-on bypass] -- CMD [ARG ...]
scrapescope serve  [common] [--upstream-from-env VAR | --direct] [--token-file PATH] [--units N]
scrapescope find URL --value V [--value V ...] [--verify] [common]
                   [--upstream-from-env VAR | --direct] [--timeout SECONDS] [--body-cap-mb N]
scrapescope report REPORT.json [--format text|html|json] [--html OUT] [--fail-on budget|bypass ...]

common: --rate USD      price per GB (per GiB with --gib); no default, costs only when given
        --gib           report in GiB (2^30) instead of GB (10^9)
        --budget SIZE   a unit is required: 2GB, 500MB, 1.5GiB, 2B for bytes (a bare number exits 2);
                        help: "the provider may count up to a few MB more per open tunnel"
        --max-tunnel-mb N   per-connection cap, N x 10^6 bytes (round 4: per upstream connection)
        --deny-host GLOB    repeatable
        --deny-catalog background   repeatable; only "background" in v1
        --out PATH      default ./scrapescope-report.json
        --html PATH     also write report.html
        --keep-urls     paths (never query strings) in reports; default hosts only
        --redact-hosts  hashed hosts / catalog ids in reports
        --quiet         no terminal summary (errors and budget messages still go to stderr);
                        round 3 (ux-r3-1), find: "no progress notes on stderr; the result and the
                        meter line still go to stdout (errors and budget messages still go to stderr)"
        --port N        main listener port; default random
        --allow-private-targets   direct routes may reach loopback, private and link-local
                        addresses (off by default; round 1)
```

Round 2 CLI notes: `find --help` says it ranks responses that contain any
`--value`, those holding every value first; its description and the epilog
list exit 6 (partly found) and 130 (Ctrl-C, no report).

Round 1 CLI notes: the `--env-all` help states the IP exposure (direct.json
hosts leave from this machine's own IP for every client of the meter). The
top-level and subcommand epilogs list every exit code inline, because
docs/exit-codes.md is not in the wheel. The serve banner's example uses `curl
--compressed`. When `HTTPS_PROXY` is unset but `https_proxy`, `all_proxy`
or `ALL_PROXY` is set, the upstream error names that variable; round 4
(ux4-4): also `HTTP_PROXY` or `http_proxy` when one of them is the only
variable set ("no upstream proxy: HTTPS_PROXY is not set, but HTTP_PROXY
is. scrapescope reads only HTTPS_PROXY by default; use --upstream-from-env
HTTP_PROXY to use it, or --direct ...").

Round 4 serve notes: `--allow-tokenless` is removed (hon4-3; the plan says
serve always requires the per-run token). Round 4 (sec4-7): `serve` prints the
token only when stderr is a terminal. Otherwise it writes
`http://ss-<token>:x@127.0.0.1:PORT` to `proxy-url`, mode 0600, in a fresh
0700 directory from `tempfile.mkdtemp(prefix="scrapescope-serve-")`, and
prints only that path. `--token-file PATH` names the file in either case:
PATH must not exist yet and is created with `O_CREAT | O_EXCL | O_WRONLY |
O_NOFOLLOW` and mode 0600 (exit 2 when it exists or cannot be created). The
file (and the temporary directory) is removed when `serve` stops. The banner
example then reads `HTTPS_PROXY="$(cat PATH)" curl --compressed ...`.
Recommended for CI (docs/security.md, "Tokens").

Round 4 (ux4-2): the terminal no longer prints the 80% line when the same
read also tripped the budget; the report's `budget_events` still list both
`warn_80` and `tripped`.

`--upstream-from-env` and `--direct` are mutually exclusive (argparse, exit 2).
Without either: `HTTPS_PROXY` if set, else exit 89 with the `ConfigError`
message suggesting `--direct`. The upstream URL is never accepted on argv.

### 12.2 Lifecycle

`run`:
1. Resolve the upstream (`config.resolve_upstream`, exit 89 on `ConfigError`),
   load catalogs, build `deny_rules` (`--deny-host` globs; `--deny-catalog
   background` expands to one `HostRule` per host glob of every background
   entry) and, with `--env-all`, `direct_rules` from direct.json.
2. `events = PrivateEventsFile.create()`, start a
   `ForwarderThread(ForwarderConfig(token=None, require_token=False, auth_listener=True, ...),
   connect_map=config.connect_map_from_env())`; startup failure exits 88.
   (Integration decision: `run` and `find` configure no token. Nothing can
   learn it, and with a token set, a provider username that happens to start
   with `ss-` would be refused as a bad token.) `--out`/`--html` are checked
   before anything starts: a missing or unwritable directory exits 2.
3. Child env from `config.build_child_env` (section 12.3); start CMD with
   `subprocess.Popen(cmd, env=..., start_new_session=True)` so it leads its own
   process group; stdio inherited. CMD not found: exit 127; not executable: 126.
4. Wait for the child. `warn_80` prints one stderr line. On `tripped`: stderr
   message naming the heaviest hosts, `killpg(SIGTERM)`, then `killpg(SIGKILL)`
   after `STOP_GRACE_S` unless the whole group has already exited (so a
   grandchild that ignores SIGTERM is still stopped). SIGINT, SIGTERM and
   SIGHUP received by scrapescope are forwarded to the child's group; a second
   SIGINT sends SIGKILL.
5. After the child exits, allow up to 1 s for tunnels to drain, then
   `stop()` for the final snapshot; `read_events`; `attribute(...,
   units_override=--units)`; `build_report(options=ReportOptions(command="run",
   ...))`; `write_report(--out, --html)`; print `render_text` to STDERR (the
   child's stdout stays clean) unless `--quiet`.
6. Delete the events directory unless `--keep-events` (then print its path).
7. Exit code per section 13.

`serve`: as run without a child; `require_token=True` always (round 4),
`auth_listener=False`; prints once to stderr the proxy URL and the username
`ss-<token>` (and that `ss-<token>~<your-proxy-user>` passes your own user)
when stderr is a terminal, otherwise (or with `--token-file`) the path of the
0600 token file instead (section 12.1, round 4 serve notes);
runs until SIGINT/SIGTERM; rewrites the report atomically every 60 s and on
exit; exit 0, or 86 when the budget tripped. `runner.serve_command` also
accepts `stop_event: threading.Event` for embedding and tests.

`find`: URL and value checks first (exit 2, never echoing either); round 1:
then, before the meter starts, a check that the Playwright package can be
imported (exit 3 with uv tool, pipx and pip commands; a Chromium that fails to
start later gets its own exit-3 message); forwarder
with `token=None`, `require_token=False`, `auth_listener=False`; `result =
asyncio.run(run_find(url, values, proxy_url=fw.url, catalogs=...,
verify=--verify, ca_file=config.test_ca_from_env(), abort_check=...))` where
the abort check ends the load when the meter saw the upstream answer 407, a
SOCKS5 auth failure, an unreachable or timed-out upstream, or a budget trip;
final snapshot; `attribute` with no events; `build_report(find_results=[result])`;
print `render_find_text(result)` plus one tunnel-measured `meter:` line to
stdout, the report path (and sizing/budget notes) to stderr unless `--quiet`;
write the report. Round 1: an unexpected exception from `run_find` is caught;
the runner writes the meter report with an error find result (warning
`find stopped with an internal error (<Class>)`) and exits 88. Outcome codes:
0 found, 1 not found, 4 blocked, 5 page load failed (`status == "error"`).
Round 2 (integrating verifier): 6 when the status is `found` but
`result.missing_values` is not empty (find-r2-9); the abort check also names
meter refusals of an `https://` target (section 7, item 10); `run_find` gets
`before_verify`, which records the tunnel ids that exist before the replay, so
the `meter:` line reports the page load and the `--verify` replay separately
(find-r2-2; the report's totals still include both); Ctrl-C returns 130
without a report.

All three meter commands raise their soft open-files limit
(`_raise_fd_limit`); `run` after starting the child. `serve` passes
`record_timeline=False`.

`report`: `load_report` (exit 2 on `ReportError`); `--html OUT` writes the HTML
file whatever `--format` is; then text (stdout, default), json (stdout) or html
(stdout unless `--html` was given); then `gate(report, --fail-on)` with
`--fail-on` repeatable (`action="append"`).

### 12.3 Child environment (`config.build_child_env`)

- Default (topology-preserving): the upstream variable (from
  `--upstream-from-env VAR`, or HTTPS_PROXY) holds the meter URL
  `http://127.0.0.1:<port>` (no credentials). Any other variable whose value is
  the same upstream URL is replaced too; nothing else changes. Round 2: proxy
  variables (`*proxy` names in any case, `NO_PROXY` excepted) are replaced when
  they name the same upstream semantically (host case, scheme-less
  `user:pass@host:port`, explicit default port, socks5 versus socks5h); other
  variables still only on an exact match. `run` prints a note, and adds a
  report warning, for any proxy variable that still names the provider's
  host:port with other credentials or another scheme
  (`config.unmetered_proxy_variables`; the variable name only, never its
  value). Round 3 (sec3-7): also for a proxy variable that names the
  upstream's host on another port or scheme, or that carries its username and
  password on another host. Such variables are not replaced, because providers
  often use the port to select sessions or countries; for a loopback upstream
  only the same port counts. The texts: "note: $NAME still names your
  upstream proxy (its host on another port or scheme, or with other
  credentials, or its credentials on another host) and was left unchanged;
  ..." at start and "$NAME still named the upstream proxy (...)" in the
  report. Round 4 (sec4-4): this check parses values leniently
  (`config._lenient_proxy_endpoint`), so `https://` (a provider's TLS port),
  `socks4://` and URLs with paths count too. A new start note and report
  warning cover `HTTP_PROXY`, `HTTPS_PROXY` and `ALL_PROXY` (either case) set
  to a proxy other than the meter (`config.other_proxy_variables`), with the
  metered variable's case twin first: "note: $NAME names another proxy and
  was left unchanged; <reason>, and that traffic goes around the meter" at
  start and "$NAME named another proxy (<reason>); any traffic that used it
  went around the meter (and is missing from these totals)" in the report.
  `<reason>` (`runner._other_proxy_reason`): "curl, Python (urllib,
  Requests, HTTPX) and Node read $https_proxy before $HTTPS_PROXY" or "Go
  reads $HTTPS_PROXY before $https_proxy" for the metered variable's case
  twin, otherwise "clients use it for http:// URLs", "clients use it for
  https:// URLs" or "clients without a scheme-specific proxy variable use
  it". None of these affect the report's `incomplete` flag.
- `--env-all`: also sets `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` and lowercase
  forms to the meter URL, `NODE_USE_ENV_PROXY=1`, and `NO_PROXY`/`no_proxy` to
  the union of their existing entries with `127.0.0.1,localhost,::1`; the
  forwarder then carries direct.json hosts direct as non-target.
- `--direct` without `--env-all` changes no proxy variables; only clients using
  the helpers or `$SCRAPESCOPE_PROXY_URL` are metered (the runner prints this
  note unless `--quiet`).
- Always: `SCRAPESCOPE_PROXY_URL` (main listener), `SCRAPESCOPE_AUTH_PROXY_URL`
  (auth listener), `SCRAPESCOPE_EVENTS` (events file); `SCRAPESCOPE_KEEP_URLS=1`
  only with `--keep-urls`; round 2 (sec2-8): `SCRAPESCOPE_UPSTREAM_ID` =
  `config.upstream_id(upstream.host, upstream.port)` when an upstream is
  configured (`build_child_env(..., upstream_id=...)`), removed otherwise.
- Test-only variables (honoured only with `SCRAPESCOPE_TESTING=1`):
  `SCRAPESCOPE_TEST_CONNECT_MAP` (JSON `{"host:port": "ip:port"}`) and
  `SCRAPESCOPE_TEST_CA` (CA bundle path for find).

## 13. Exit codes

| Code | Meaning |
|---|---|
| child's code | `run`: the child's own exit code when no meter condition applies; a child killed by signal N gives 128+N |
| 0 | `serve` stopped normally; `find` found every value (round 2; before: at least one match); `report` passed its gates |
| 1 | `find`: not found in any inspected response |
| 6 | `find`: partly found: status `found`, but at least one value in no inspected response (round 2, find-r2-9) |
| 130 | `find` interrupted with Ctrl-C; no report is written (round 2) |
| 2 | usage error (argparse), including an unreadable or invalid report file for `report` and `--budget` without a unit |
| 3 | `find`: Playwright or Chromium not installed (the message gives uv tool, pipx and pip commands, or `playwright install chromium` when only Chromium fails) |
| 4 | `find`: the page was a challenge page ("blocked; cannot search"); round 1 |
| 5 | `find`: the page load failed (navigation error, timeout, 407 or unreachable upstream; round 2: or the meter refused the target: private address, deny rule, self-loop, or the meter's own reply as the main document); round 1 |
| 86 | budget tripped (`run`, `serve`, `find`); `report --fail-on budget` on a tripped report |
| 87 | bypass detected with `run --fail-on bypass`; `report --fail-on bypass` on an incomplete report |
| 88 | meter internal error (forwarder failed to start or crashed), or an unexpected error inside `find` (the report is still written) |
| 89 | upstream configuration error before start (bad scheme, missing variable) |
| 126 / 127 | `run`: CMD not executable / not found |

Precedence in `run`: 88, then 86, then 87, then the child's code. In `find`:
88, then 86, then the outcome (0, 6, 1, 4, 5).

## 14. Privacy and security invariants

Tests should enforce these wherever they apply:

1. The upstream URL, host, port, username and password never appear in stdout,
   stderr, logs, report.json, report.html or the events file, on success and
   on every error path (upstream unreachable, 407, upstream DNS failure, TLS
   error at the client, SOCKS auth failure). Check the Basic base64 form too.
2. Reports never contain bodies, query strings, cookies, header values,
   credentials, the command line, environment values or find values; paths only
   with `--keep-urls`.
3. Every untrusted string is sanitised (`clean_host`/`clean_path`/`safe_text`)
   and HTML-escaped in report.html; fixtures include `<script>`, `javascript:`
   and Markdown image syntax in paths.
4. The forwarder binds 127.0.0.1 only, refuses origin-form requests with a bare
   403, refuses absolute-form https with 400, refuses self-loops, never
   terminates TLS, and never resolves target hostnames on http-connect or
   socks5 routes when an upstream is configured. The one exception is
   direct.json hosts under `run --env-all`, which the meter resolves and
   connects to from this machine's own IP (announced at start and in the
   report). In sizing mode it refuses non-global destinations unless
   `allow_private_targets`.
5. The events file is 0600 in a 0700 directory, deleted after the run unless
   `--keep-events`, and carries metadata only.
6. No network calls except the job, find's page load and the one verify request.
7. `serve` always requires the token (round 4: `--allow-tokenless` removed),
   and prints it only to a terminal or a 0600 token file; `run` and `find`
   accept tokenless loopback connections for their lifetime (browsers' own
   background fetches cannot answer a 407), documented in docs/security.md.

  and bytes on their side of the socket, which must equal the meter's
  `upstream_bytes_*`. Credentials: `tests.fixtures.UPSTREAM_USERNAME`,
  `UPSTREAM_PASSWORD`, and any username with `SESSION_PASSWORD` (session
  usernames). Site content and marker constants live in `tests.fixtures.site`
  (`PRODUCT_PRICE`, `PRODUCT_SKU`, `SIGNED_QUERY_TOKEN`, `NEXT_DATA_MARKER`,
  `BEACON_SEQ`, `HOSTILE_PATHS`, ...); never hard-code them.

- Every test has a timeout (pytest-timeout, default 60 s in pyproject); mark

- No test touches the internet or real DNS.
- Prefer testing your module against fixtures plus `types`/`config` only;
  cross-module end-to-end tests belong to the integrator.

## 16. Architect decisions (additions to the brief)

1. **`kind` plus `route`.** `TunnelRecord.kind` is the client form (`connect`
   or `http`); `route` is how it left (`http-connect`, `socks5`, `direct`,
   `non-target`, `refused`). The brief's example kinds such as "socks-direct"
   are expressed by this pair.
2. **Auth listener.** `run` and `find` open a second loopback port that answers
   407 when no credentials are sent (`SCRAPESCOPE_AUTH_PROXY_URL`). It is what
   makes per-context credential pass-through work, because Chromium only sends
   proxy credentials after a challenge (section 5.2).
3. **Events extras.** Optional `context` on attach/request and `pid` on
   attach/launch, needed for "cache loss not modelled" (per-context page
   counts). Helpers emit only network schemes.
4. **Report extras.** `command`, `labels`, `budget`, `refused`, `helper_events`,
   `bypass`, `hosts[].ports/paths/background_id`, `find[].coverage.line`,
   `buckets.attributed` (so buckets sum to the total).
5. **Units** exclude 3xx responses (redirect hops are not pages).
6. **find exit codes** 1 (not found; round 1 split out 4 blocked and 5 load error) and 3 (browser missing);
   `run` uses 126/127 for a missing or non-executable CMD; `serve` exits 86 when
   its budget tripped.
7. **Duplicate proxy variables** holding the same upstream URL are replaced too
   (otherwise the child would bypass the meter and keep the credentials).
   Round 2: proxy variables are compared semantically (host case, scheme-less
   form, explicit default port, socks5 versus socks5h), and one that still
   names the provider's host:port with other credentials or another scheme
   gets a start note and a report warning (section 12.3).
8. **Keep-alive authority switch** on a plain-HTTP connection starts a new
   TunnelRecord, keeping per-host counts exact. Round 3 (meas3-3): on the
   `http-connect` route the provider connection is kept (`continued_from`),
   as the client kept it; other routes open a new upstream connection.
9. **Host globs** support only `*` (zero or more characters, dots included).
10. **Timeline** at 0.25 s resolution drives `bytes_before_first_navigation`
    and first-unit-versus-rest figures, which are therefore approximate.
11. **`--redact-hosts`** uses `catalog:<id>` for catalogued hosts and a
    per-report keyed hash `redacted:<12 hex>` for others (a plain hash of a
    hostname is reversible by dictionary).
12. **Terminal summary on stderr for `run`/`serve`** so the child's stdout stays
    clean; `find` prints its result on stdout.
13. **SOCKS5 auth failure** returns 502 `socks-auth-failed`, not 407, to avoid
    browser re-authentication loops against a failure the client cannot fix.
14. **`https://` upstream URLs** (TLS to the proxy) are rejected in v1 with exit 89.

### 16.1 Integration decisions (integrator, 2026-09-23)

15. **No token in `run` and `find`.** Their listeners are tokenless on
    loopback by design, so a token would only make provider usernames that
    start with `ss-` fail. `serve` keeps the token.
16. **`PRECONNECT_IDLE_MAX_SENT = 3072`**, not 2048: the brief says "about
    2 KB up", but Chromium 153's post-quantum ClientHello (X25519MLKEM768) makes
    a real idle preconnect send 2.0-2.3 KB of payload.
17. **Timeline straddle rule** for `bytes_before_first_navigation` and
    `per_unit` (section 6, step 10).
18. **`find` asks for Chromium's OS sandbox** and falls back with a warning.
19. **Report paths are checked before the job starts** (exit 2), so a long
    job never ends with an unwritable report.
20. **`run` forwards SIGHUP** as well as SIGINT and SIGTERM, and escalates to
    SIGKILL after the grace period even when the group leader already exited.
21. **Terminal-only `meter:` line for `find`**, giving the page load's
    tunnel-measured totals next to the DevTools-based ranking.
22. **`report.write_html`** added for `report --html`.

### 16.2 Round 1 decisions (integrating verifier, 2026-09-23)

23. **direct.json holds LLM APIs only.** The plan (section 5, Appendix A)
    lists cloud-storage API hosts too. They were removed: bucket hosts
    (`*.s3.amazonaws.com`, `*.blob.core.windows.net` and similar) are often the
    very hosts a scraper targets, and under `--env-all` they would leave from
    the user's own IP address, exposing it to the bucket owner and dropping
    those bytes from totals and the budget. `--env-all` with a provider still
    carries the LLM hosts direct, as the plan requires, and says so.
24. **find exit codes 4 (blocked) and 5 (page load failed)** so scripts never
    read "blocked" as "not found" (plan: "never 'not found'"); an internal
    error inside find exits 88 with the report written.
25. **User-Agent without a URL** until the public repository exists and
    resolves; `[project.urls]` is absent for the same reason. A dead URL would
    give site operators a contact anyone could register.
    `scripts/release_check.py` and docs/dev/release-checklist.md gate the
    release on the maintainer name, the URLs and absolute README links.
    (Superseded on 2026-09-24: the repository is
    https://github.com/ipvolt/scrapescope; the contact URL and
    `[project.urls]` were added, and `github.com/scrapescope` left
    `UNRESERVED_NAMESPACES`, which now lists the PyPI project name instead.)
26. **`h11>=0.16`** (GHSA-vqfr-h8mv-ghfj / CVE-2025-43859).
27. **Golden reports are generated** by `scripts/make_example_reports.py` from
    the real builders, and a test keeps them current.
28. **Schema additions** (optional fields, so older round-0 reports still
    validate): `findMatch.content_encoding`, `findMatch.multiplexed`,
    `findMatch.locations_by_value`, `verify.replay_billed_basis_bytes`, the
    coverage reason `challenge`, and `text`/`code` patterns covering Unicode
    categories Cc, Cf, Zl, Zp and Cs.

### 16.3 Round 2 decisions (integrating verifier, 2026-09-23)

29. **find exit 6 for a partial result** (find-r2-9). A `found` result with a
    value in no inspected response exits 6, not 0, so `find ... && next`
    stops. `FindResult.status` stays `found` (no schema change); the terminal
    field `FindResult.missing_values` and the `not found: value N` warning
    carry the detail.
30. **First-request timeout** (sec2-6). A connection without one complete
    request head 60 s after accept is closed (`FIRST_REQUEST_TIMEOUT_S`); the
    600 s minimum idle timeout (`MIN_IDLE_TIMEOUT_S`) is unchanged for
    connections that sent a request.
31. **Direct-mode CONNECT estimate from the client's own head** (meas2-9),
    without `Proxy-Authorization`; the docs state what is not included.
32. **Report diagnostics fields** `tunnel_failures` and `accept_limit_errors`,
    optional in the schema (docs-2).
33. **Schema `$id` = `urn:scrapescope:report:v1`** and a packaging test that
    scans every file the wheel and sdist carry (from pyproject's build
    targets) and any built archive in `dist/` for URLs under an unreserved
    namespace (`scripts/release_check.py`, `UNRESERVED_NAMESPACES`).
34. **challenges.json**: verify-page rules need a challenge status; cookie-
    and header-only rules of DataDome, HUMAN, Akamai and Imperva leave out
    503 (find-r2-6).
35. **One path-token heuristic** in `types.is_path_token_segment` (sec2-12).
36. **`SCRAPESCOPE_UPSTREAM_ID`** set by `run` (sec2-8); `upstream_id` moved
    to config (the helper re-exports it).
37. **WebRTC**: `find` always restricts WebRTC to proxied connections; the
    Playwright helper offers `launch(..., webrtc_proxied_only=True)`, off by
    default because it changes what the user's pages can do (sec2-1).
38. **No first-class `no_network` field** (meas2-1): the optional events key
    and the intake subclass stay; the report keeps one combined line.
39. **Classifiers** list only what the suite has run on (macOS, Python 3.12);
    `.github/workflows/ci.yml` (actions pinned to commit SHAs on 2026-09-24;
    not yet run) covers Linux and 3.11-3.14 and
    builds, installs and exercises the wheel (pkg-1). `h2` is a dev extra for
    the real HTTP/2 hook test, which is skipped where it is not installed
    (meas2-5).

### 16.4 Round 3 decisions (integrating verifier, 2026-09-23)

40. **Plain-HTTP provider connections are kept across authorities** on the
    `http-connect` route (meas3-3); a new TunnelRecord with `continued_from`
    marks each switch, and consumers that mean connections count
    `opened_connection` (the session-reuse fix does). Report "tunnels" still
    count records; no schema change.
41. **Sizing mode refuses this machine and its IPv6 /64** after connect and
    before the first byte (sec3-1), with the IPv4 netmask limit documented.
42. **IP literals are canonical** in every check and record (sec3-5); the
    provider still receives the client's spelling on HTTP CONNECT.
43. **One share line** for terminal and report (find3-1): the report renders
    `find.render.share_line`; `report._fmt.best_match_share` (the old
    TLS-inclusive tuple) is gone.
44. **Challenge rules need a source that contains them** (find3-8/9): the two
    hard-block rules cite the vendors' own documentation and fire on 403 only;
    `recaptcha:captcha-form` and `human:block-page` need 403 or 429.
45. **Sizing-mode plain HTTP is documented, not estimated** (meas3-9): adding
    a per-request absolute-form estimate would still leave out the
    credentials line, the larger part; the docs say what is missing.
46. **Tunnel records stay uncapped in v1** (sec3-9); the measured cost (about
    0.8 kB per record) and the deny-rule growth path are documented in
    docs/security.md. Aggregating refused records is a candidate for v1.1.
47. **The suite runs without the `[browser]` extra** (pkg-r3-1): non-browser
    tests fake find or skip on a missing Playwright, and
    `tests/test_packaging.py::test_the_suite_without_the_browser_extra_needs_no_playwright`
    runs them in a subprocess with Playwright made unimportable
    (`tests/_no_playwright.py`).
48. **Overlapping units are not detected** (meas3-4): events carry no unit end
    time, so the per-unit split is withheld only by the start-gap rule
    (section 6, step 10).

Events file:

> EVENTS FILE (JSONL, helper -> meter; one JSON object per line, version field
> v=1): kinds "attach", "launch" (browser launch), "request" with fields: ts,
> source (playwright|requests|httpx), host, port, scheme, path (ONLY when

> (bool), sent_authorization (bool). Never bodies, cookies, header values,

report.json:

> catalog_versions, started_at, ended_at, mode (direct | http-connect | socks5
> — never the upstream host), gb_unit, totals {with_connect, without_connect,
> tunnels, failed_tunnels}, units {count, source}, browser_launches,
> bytes_before_first_navigation, per-unit bytes (first unit vs rest), hosts[]
